# Глава 8. Реверс (Reverse Engineering)

Реверс - это "понять, что делает программа, которую тебе дали". Пугает из-за скомпилированных
бинарников, но на муниципале задачи обычно сводятся к одному: **найти, как программа проверяет
правильный ответ/пароль, и восстановить его**. Это прямое продолжение п. 4.12 (писать дешифратор):
ты читаешь чужую логику и обращаешь её. Общий порядок мыслей при решении - в п. 8.6.

---

## 8.1. Два вида реверс-задач

| Что дали | Сложность | Подход |
|---|---|---|
| **Скрипт** (Python, JS, .pyc) | проще | читаешь исходник глазами |
| **Скомпилированный бинарник** (ELF, .exe) | сложнее | `strings`, затем декомпилятор (Ghidra) |

С первого и начинай всегда: если код читаемый - не нужен никакой декомпилятор.

---

## 8.2. Если дали скрипт - просто читаем

Python/JS-скрипт - это уже исходник. Открываешь и ищешь, **где проверяется правильность**:

```python
# типичная проверка пароля в скрипте
user = input("Password: ")
if user == "sup3r_s3cr3t":        # <- пароль прямо в коде!
    print("flag{...}")
```

Бывает "запутаннее" (обфускация): имена переменных заменены на мусор, строки собираются из кусков,
есть лишние преобразования. Приёмы:

- Не пытайся понять **всё** - найди строку с `if ... == ...`, `print(flag)`, проверку длины.
- Если флаг/пароль собирается вычислением - **запусти кусок кода сам** и посмотри результат
  (можно `print()` промежуточных значений).
- `.pyc` (скомпилированный Python): `uncompyle6`/`decompyle3` часто НЕ поддерживают Python 3.9+
  (а он на всех олимпиадных ВМ). Зато встроенный `dis` работает всегда и офлайн - выгрузит все
  константы, строки и сравнения из байткода:
  ```bash
  python3 -c "import marshal,dis; f=open('task.pyc','rb'); f.seek(16); dis.dis(marshal.load(f))"
  ```

💡 Мощнейший приём для скриптов: **вставь `print()`** перед проверкой и выведи то, с чем сравнивают.
Часто это и есть ответ - не нужно даже "обращать" логику.

🎯 **Тренировка 23.** Напиши скрипт, который принимает пароль и сравнивает с "секретом", собранным
из кусков (`s = chr(115)+chr(51)+...`). Потом "глазами реверсера" найди способ узнать пароль, не
подбирая: вставь `print(секрет)` или посчитай выражение в интерактивном Python.

## 8.3. Скомпилированный бинарник - первые шаги

Дали ELF (или `.exe`). Паниковать не надо - сначала лёгкие проверки из главы 2:

```bash
file program            # архитектура, 64/32 бит, stripped или нет
strings program | less  # читаемые строки: подсказки, формат вывода, иногда пароль
strings program | grep -iE 'flag|password|correct|wrong|enter'
```

Очень часто `strings` сразу показывает структуру: `"Enter password: "`, `"Correct!"`, `"Wrong"`, а
иногда и сам флаг/пароль, если он лежит в бинаре строкой. С этого всегда и начинай.

### `strace` - что программа делает в системе

```bash
strace ./program        # показать системные вызовы (открытие файлов, чтение/запись)
ltrace ./program        # показать вызовы библиотечных функций (strcmp, printf...) - если установлен
```

💡 `ltrace` особенно полезен: если программа сравнивает твой ввод с паролем через `strcmp`, в выводе
`ltrace` будет видно **оба аргумента** - и твой ввод, и настоящий пароль, прямо открытым текстом.

## 8.4. Декомпилятор Ghidra - куда нажимать

Когда `strings` не хватает, нужен **декомпилятор** - он превращает машинный код обратно в
C-подобный псевдокод. Бесплатный стандарт - **Ghidra** (есть в образе).

> Подробный разбор Ghidra со скриншотами - в отдельной главе [`ghidra.md`](ghidra.md): проект,
> импорт, анализ, переименование и типы, патчинг, копирование массива в Python.

Минимальный маршрут:

1. Запусти Ghidra -> *New Project* -> перетащи бинарник -> согласись на анализ (*Analyze* -> Yes).
2. Слева в **Symbol Tree** -> *Functions* найди **`main`** (точка входа; если бинарь stripped и
   `main` не видно - ищи `entry` или функцию, откуда идёт вывод строк).
3. Дважды кликни `main` -> справа откроется окно **Decompile** с псевдокодом на C.
4. Читай псевдокод как обычный код: ищи `if`, сравнения, циклы, вызовы `strcmp`/`memcmp`.

Что искать в псевдокоде:
- `if (strcmp(input, "...") == 0)` - пароль лежит прямо в кавычках.
- цикл, где каждый символ ввода преобразуют и сравнивают с массивом-"эталоном" - это шифр из п. 4.12,
  восстанавливается обращением или перебором каждого байта.
- вызов функции, печатающей флаг, - посмотри, при каком условии она вызывается.

💡 Не бойся незнакомых конструкций в псевдокоде. Твоя цель - **найти условие победы** и то, что
сравнивают. Всё остальное можно пролистать.

💡 Три приёма в Ghidra, что экономят новичку полчаса:
1. **Defined Strings** (Window -> Defined Strings): на stripped-бинарнике без `main` найди строку
   `"Enter password"`/`"Correct"` и по ссылке **XREF** (справа) прыгни прямо в функцию проверки.
2. **Число -> символ**: правый клик по числу в псевдокоде (`== 0x66`) -> *Convert -> Char*,
   и оно станет читаемой буквой `'f'`.
3. Массив-эталон обычно показан как `DAT_00102010` - дважды кликни по нему, увидишь сами байты
   `59 4f 49...` (скопировать: *Copy Special -> Python List / Byte String*).

## 8.5. Разбор: проверка пароля через преобразование (типовая задача)

Самый частый бинарный реверс на муниципале/регионе: программа преобразует введённый пароль и
сравнивает с "эталоном", зашитым в коде. В декомпиляторе это выглядит примерно так (псевдокод C):

```c
char target[] = {0x59,0x4f,0x49,0x58,0x4f,0x5e,0x13,0x13};  // эталон в коде
for (int i = 0; i < 8; i++) {
    if ((input[i] ^ 0x2A) != target[i])    // каждый символ XOR 0x2A, сравнить с эталоном
        return WRONG;
}
return CORRECT;                             // совпало - пароль верный
```

Логика: `пароль[i] ^ 0x2A == target[i]`. Значит `пароль[i] = target[i] ^ 0x2A` (XOR сам себе
обратный - п. 4.11). Восстанавливаем пароль в одну строку Python:

```python
target = [0x59, 0x4f, 0x49, 0x58, 0x4f, 0x5e, 0x13, 0x13]
password = bytes(x ^ 0x2A for x in target)
print(password)          # -> b'secret99'
```

Вводишь `secret99` в программу - получаешь флаг. Это и есть суть реверса: **прочитал проверку ->
обратил её -> получил нужный вход**.

🔺 Если преобразование сложное (несколько операций, состояние) - обращаешь его по правилам п. 4.12 или
**подбираешь каждый байт перебором** (все 256 значений для каждой позиции, как в п. 4.12). Перебор
работает всегда, пока символы проверяются независимо, - и часто это проще, чем выводить формулу.

🎯 **Тренировка 24.** Вернись к п. 4.12 и реши её "реверс-постановку": дан массив `target` и операция
преобразования - восстанови вход и перебором, и через обратную формулу. Это ровно то, что ждёт в
бинарном реверсе, только там операцию ты прочитал в Ghidra.

## 8.6. Как думать на реверсе

Инструменты - это руки, а решает голова: в каком порядке задавать себе вопросы. Ниже порядок мыслей,
который работает почти на любой задаче муниципала (и региона тоже).

### Главная модель: вход -> проверка -> "да"/"нет"

Любой крякми - это функция: получает вход, проверяет и отвечает "да" или "нет". Понимать программу
целиком **не нужно**. Нужно найти такой вход, при котором будет "да". Путей всего три:

| Путь | Когда работает | Как |
|---|---|---|
| **Подсмотреть** | ответ лежит в программе как есть | `strings`, `ltrace`, строка в псевдокоде |
| **Обратить** | вход преобразуют и сравнивают с эталоном | переписать проверку на Python и отменить операции |
| **Обойти** | флаг зашит в ветке "успех" и не зависит от ввода | патч перехода, gdb (см. hard) |

Пробуй их именно в этом порядке, от дешёвого к дорогому: подсмотреть - минута, обратить - минут
десять-двадцать, обходить - когда первые два не вышли.

### Иди от конца, а не от начала

Новичок открывает `main` и читает сверху вниз всё подряд - и тонет. Делай наоборот:

1. Найди **точку победы**: строку `Correct`/`flag`, вызов `puts` с флагом (Defined Strings -> XREF).
2. Поднимись на шаг вверх: **какое условие** ведёт к этой строке? Например, `if (check(buf) == 1)`.
3. Зайди в это условие и спроси: **что с чем сравнивают?**
4. Всё, что на это сравнение не влияет (меню, печать, проверки ошибок), пропускай.

### Пять вопросов к проверке

Нашёл функцию проверки - ответь на пять вопросов. Лучше письменно, прямо комментариями в будущем
скрипте:

1. **Что на входе?** Строка, число, файл? Какой длины? (`strlen(s) != 10` - уже подсказка.)
2. **С чем сравнивают?** Готовая строка, массив-эталон, хеш?
3. **Что делают со входом до сравнения?** Выпиши операции строго по порядку.
4. **Байты независимы?** Каждый символ проверяется сам по себе или зависит от соседей?
5. **Операции обратимы?** XOR, `+`, `-`, циклический сдвиг, перестановка - да. Хеш, `%`, `&` с
   потерей битов - нет, тогда перебор.

Ответы прямо подсказывают, что делать:

| Что выяснил | Что делать |
|---|---|
| сравнивают с готовой строкой | подсмотреть: `strings`, `ltrace` |
| операции обратимы, байты независимы | обратить формулу (или перебор по байту) |
| операция необратима, байты независимы | перебор 0..255 для каждой позиции |
| байты связаны между собой | z3 или перебор маленькими кусками (hard) |
| хеш от всей строки | перебор по словарю/короткому алфавиту (`04-crypto/hard.md`) |
| флаг печатается в ветке успеха и от ввода не зависит | патч перехода (hard) |

### Перепиши проверку на Python - и проверь модель

Это ключевой навык. Прежде чем что-то обращать, перепиши проверку **на Python один в один**. Потом
проверь модель: дай ей свой вход и убедись, что она ведёт себя как программа. Модель без проверки -
гадание: одна забытая `& 0xFF` или перепутанный индекс, и ответ неверный.

Обращение - это **те же операции в обратном порядке, каждая заменена на обратную** (п. 4.12):
`+5 -> -5`, `^k -> ^k`, `rol -> ror`, разворот строки -> разворот обратно.

### Разбор: как это выглядит в голове

Синтетический крякми `crackme2` (исходник в [`lab/crackme2.c`](lab/crackme2.c)). Псевдокод проверки
после переименования переменных в Ghidra выглядит примерно так:

```c
int check(char *s) {
    unsigned char t[] = {0x26,0x65,0x3c,0x73,0x41,0x68,0x52,0x68,0x30,0x6e};
    if (strlen(s) != 10) return 0;
    for (int i = 0; i < 10; i++) {
        unsigned char c = s[9 - i];        // символы берут с конца
        c = (c ^ (i * 3)) + 5;             // XOR с номером*3, потом +5
        if (c != t[i]) return 0;
    }
    return 1;
}
```

Отвечаем на пять вопросов:

1. Вход - строка длины **10**.
2. Сравнивают с массивом `t`.
3. По порядку: взять символ **с конца** (`s[9 - i]`) -> `^ (i*3)` -> `+ 5` (тип `unsigned char`,
   значит всё по модулю 256).
4. `t[i]` зависит от одного символа и номера `i` - байты независимы.
5. Всё обратимо. Обращаем в обратном порядке: `-5`, потом `^ (i*3)`, потом разворот.

```python
t = [0x26, 0x65, 0x3c, 0x73, 0x41, 0x68, 0x52, 0x68, 0x30, 0x6e]

def model(s):                          # шаг 1: та же проверка, но на Python
    return [((s[9 - i] ^ (i * 3)) + 5) & 0xFF for i in range(10)]

print(model(b"AAAAAAAAAA")[:3])        # проверили модель на своём вводе -> [70, 71, 76]

rev = []
for i in range(10):                    # шаг 2: обратные операции в обратном порядке
    c = (t[i] - 5) & 0xFF              # сначала отменяем +5
    c = c ^ (i * 3)                    # потом XOR (он сам себе обратный)
    rev.append(c)
pw = bytes(rev)[::-1]                  # шаг 3: отменяем разворот
print(pw)                              # -> b'r3v_l0g1c!'
print(model(pw) == t)                  # шаг 4: прогнали ответ через модель -> True
```

Шаг 4 обязателен: сначала ответ проходит через твою модель, и только потом идёт в программу:

```
$ ./crackme2
Password: r3v_l0g1c!
Correct! flag{th1nk_b4ckw4rds}
```

💡 Не уверен в обращении - **перебери по байту** (байты ведь независимы). Тут почти невозможно
ошибиться, потому что ты используешь прямую формулу из программы, а не обратную:

```python
t = [0x26, 0x65, 0x3c, 0x73, 0x41, 0x68, 0x52, 0x68, 0x30, 0x6e]   # эталон из программы (как выше)
pw = bytearray(10)
for i in range(10):
    for ch in range(256):                          # все варианты символа
        if ((ch ^ (i * 3)) + 5) & 0xFF == t[i]:    # прямая формула из программы
            pw[9 - i] = ch                         # не забыли разворот: позиция 9 - i
            break
print(bytes(pw))                                   # -> b'r3v_l0g1c!'
```

### Когда застрял

- Читаешь 15 минут и ничего не ясно - вернись к "иди от конца". Возможно, разбираешь не ту функцию.
- Переименуй всё, что понял (`L` в Ghidra): `local_48 -> buf`, `iVar1 -> ok`. От имён половина
  "непонятного" кода становится понятной.
- Непонятная операция - перепиши кусок на Python и посмотри, что он делает с `AAAA`. Эксперимент
  быстрее чтения.
- Ответ "почти верный" (часть символов мусор) - ищи ошибку в модели: забытое `& 0xFF`, знаковый
  `char` вместо `unsigned char`, индекс сдвинут на 1.
- Совсем глухо - смени путь: не вышло обратить -> перебор; перебор долгий -> патч или отладчик (hard).

## 8.7. Реверс: "вижу X -> делаю Y"

| Что видишь | Что делать |
|---|---|
| `.py` / `.js` скрипт | читать исходник; `print()` перед проверкой |
| `.pyc` | декомпилировать (`uncompyle6`), или `strings` |
| ELF/.exe | `file` -> `strings \| grep` -> если мало, Ghidra |
| в strings виден пароль/флаг | сразу использовать |
| сравнение через `strcmp` | `ltrace ./bin` покажет оба аргумента |
| цикл "преобразование + сравнение с массивом" | обратить (п. 4.12) или перебрать по байту |
| условие печати флага | понять, что его включает |
| не понимаю, с чего начать | п. 8.6: от точки победы назад, пять вопросов |

> Скомпилированный файл больше не пугает: `file`, `strings`, `ltrace`, в сложном случае - `main` в
> Ghidra. Находишь, как программа проверяет ответ, и обращаешь проверку - теми же руками, что в
> криптографии. По сути реверс и крипта - одно и то же с разных сторон. Дальше - Pwn, для знакомства.
