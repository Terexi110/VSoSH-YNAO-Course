# Глава 5. Форензика и стеганография

Эти две категории ищут данные, спрятанные в файлах.

- **Форензика (Forensics)** восстанавливает скрытые, удалённые или замаскированные данные из файлов,
  образов дисков и дампов трафика.
- **Стеганография (Stego)** прячет данные **внутри** другого файла так, чтобы внешне он выглядел обычным.

Криптография **скрывает смысл** сообщения, стеганография - **сам факт** передачи. На CTF обе категории
решаются набором утилит плюс знакомыми `strings`, `xxd` и Python.

---

## 5.1. Тот же ритуал, но глубже

Любой файл из этих категорий начинай проверять одинаково:

```bash
file   подозрительный            # что это на самом деле?
strings подозрительный | grep -i '{'   # флаг лежит открыто?
xxd    подозрительный | head     # магические байты, аномалии в начале
binwalk подозрительный           # нет ли ВНУТРИ других файлов?
exiftool подозрительный          # что в метаданных?
```

Эти пять команд решают большую часть лёгких форензик-задач. Разберём неочевидные случаи.

💡 Сначала попробуй `strings файл | grep flag`: это бесплатно и часто сразу даёт ответ.

💡 В файлах из Windows строки могут быть в UTF-16, и обычный `strings` их не найдёт.
Добавь `strings -e l файл | grep -i flag` (`-e l` - little-endian UTF-16).

## 5.2. Метаданные - `exiftool`

**Метаданные** - служебная информация файла: автор, камера, дата, GPS, комментарии, описание.
Флаг часто прячут именно туда.

```bash
exiftool image.jpg          # вывести ВСЕ метаданные
exiftool image.jpg | grep -i -E 'flag|comment|gps|author|description'
```

Проверь `Comment`, `Image Description`, `Artist`/`Author`, `Make`/`Model`, `GPS Position`, `Software`:
модель камеры бывает подсказкой, а GPS ведёт к нужному месту.

**Если `exiftool` недоступен, EXIF можно прочитать через Pillow:**

```python
from PIL import Image
img = Image.open("image.jpg")
exif = img.getexif()
for tag_id, value in exif.items():
    print(hex(tag_id), value)     # 0x010e = ImageDescription, 0x0110 = Model, ...
# частые теги: 0x010e Описание, 0x0110 Модель, 0x013b Автор, 0x8298 Copyright
```

⚠️ Проверяй метаданные также у офисных документов и аудио. У PDF команда `exiftool doc.pdf`
покажет, в частности, `Author`, `Keywords`, `Title`.

🎯 **Тренировка 13.** Создай картинку и запиши в EXIF описание `flag{...}`
(`exif = img.getexif(); exif[0x010e] = "flag{meta}"; img.save("m.jpg", exif=exif)`), затем прочитай
его через `getexif()`.

## 5.3. Склеенные и вложенные файлы - `binwalk` / `foremost`

Частый приём: в конец картинки **дописан** архив или другой файл. PNG открывается, потому что
программа читает до маркера конца, а «хвост» остаётся незаметным.

**Поиск вложений - `binwalk`:**

```bash
binwalk image.png            # покажет найденные сигнатуры: Zip archive, PNG, gzip, ...
binwalk -e image.png         # -e = extract: сразу извлечь всё найденное в папку _image.png.extracted/
```

**Альтернатива - `foremost`** (вырезает файлы по сигнатурам):

```bash
foremost -i image.png -o out_dir   # извлечённое ляжет в out_dir/
```

**Как вырезать вложение вручную.** Каждый формат начинается со своей сигнатуры (глава 2).
Найди сигнатуру архива внутри файла и скопируй всё от неё до конца:

```python
data = open("glued.png", "rb").read()
idx = data.find(b"PK\x03\x04")      # сигнатура ZIP-архива
print("ZIP начинается со смещения", idx)
open("carved.zip", "wb").write(data[idx:])   # вырезаем всё от сигнатуры до конца
# теперь: unzip carved.zip
```

💡 Вырезанный архив часто защищён словарным паролем - перебери его через `john`:
```bash
zip2john carved.zip > hash.txt && john hash.txt --wordlist=wordlist.txt
# john hash.txt --show  # показать найденный пароль; перебор без утилит - на zipfile (10-misc medium)
```

💡 Быстрая проверка склейки: `strings image.png | grep flag`. Если флаг дописан текстом,
он найдётся сразу; иначе запускай `binwalk`.

🎯 **Тренировка 14.** Склей картинку и ZIP: `cat cover.png secret.zip > glued.png`.
Убедись, что картинка открывается, затем достань архив тремя способами: `binwalk -e`,
ручным поиском `PK` в Python и `unzip glued.png`.

## 5.4. Стего в картинках: LSB

**LSB (Least Significant Bit)** - самый частый приём стеганографии в картинках. Младший бит
цветового байта почти не влияет на цвет, поэтому в него можно записать сообщение.

```
Пиксель R = 10110110 -> меняем последний бит на бит секрета -> 10110111
                   ^                                               ^
          почти не влияет на цвет                        но несёт 1 бит данных
```

**Готовые инструменты:**

```bash
zsteg image.png              # автоматически перебирает LSB-схемы для PNG/BMP - часто сразу флаг
zsteg -a image.png           # -a = все методы
```

`stegsolve` - графическая утилита для просмотра битовых плоскостей, XOR каналов и разницы изображений.
Листай плоскости стрелками: так можно увидеть скрытый текст или **изображение**.

**Как достать LSB вручную на Python:**

```python
from PIL import Image
import numpy as np

img = Image.open("image.png").convert("RGB")
flat = np.array(img).flatten()          # все байты R,G,B подряд

# собираем младшие биты в байты
bits = ''.join(str(b & 1) for b in flat)
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))

# ищем читаемый кусок / флаг
import re
m = re.search(rb'flag\{[^}]+\}', data)
print(m.group() if m else data[:64])
```

⚠️ Если «в лоб» не вышло, перебери порядок каналов (RGB или один канал), номер бита, порядок бит
в байтах и направление обхода (по строкам или столбцам). Именно это делает `zsteg -a`, поэтому
начинай с него.

🎯 **Тренировка 15.** Зашей `flag{...}` в младшие биты пикселей (`flat[i] = (flat[i] & 0xFE) | bit`),
сохрани PNG и достань сообщение скриптом выше. Сравни картинки: на глаз разницы не будет.

## 5.5. Стего с паролем - `steghide`

`steghide` прячет данные в JPEG/BMP/WAV/AU и **защищает их паролем**. Если в `.jpg` или `.wav`
`binwalk`, `zsteg` и `strings` ничего не нашли, проверь `steghide`.

```bash
steghide extract -sf image.jpg               # спросит пароль
steghide extract -sf image.jpg -p "пароль"   # если пароль известен/угадан
steghide info image.jpg                      # есть ли вообще вложение
```

💡 Пароль часто пустой или лежит рядом: в имени файла, метаданных, условии. Если пароль неизвестен,
перебери его офлайн утилитой `stegseek` по словарю:

```bash
stegseek image.jpg wordlist.txt      # быстрый перебор пароля по словарю
```

## 5.6. Фокусы со структурой файла (особенно PNG)

Иногда файл намеренно «сломан» - в этом и состоит задача.

- **Неверные размеры PNG.** Ширина и высота записаны в заголовке. Если их занизили, часть картинки
  с флагом не отрисовывается. Размеры правят в hex-редакторе; структуру проверяют так:
  ```bash
  pngcheck -v image.png        # покажет структуру чанков и ошибки
  ```
  ⚠️ После правки размеров пересчитай CRC чанка IHDR (см. `hard.md`).
  `from PIL import ImageFile; ImageFile.LOAD_TRUNCATED_IMAGES = True` иногда помогает прочитать
  усечённые данные в Pillow, но не заменяет исправление CRC.
- **Данные после конца файла.** У JPEG файл заканчивается байтами `FF D9`, у PNG - чанком `IEND`.
  Всё после них - спрятанный «хвост» (п. 5.3).
- **Подменённое расширение.** `file` покажет настоящий тип; переименуй файл и открывай правильно.

💡 Общий принцип: открой файл в `xxd ... | less` и сравни начало и конец с ожидаемой структурой.
Аномалия часто и есть решение.

## 5.7. Анализ трафика - дампы `.pcap` / `.pcapng`

Файлы `.pcap`/`.pcapng` содержат **записанный сетевой трафик**. Их открывают в **Wireshark**;
обычно нужно найти среди пакетов флаг, файл или пароль.

### Работа в Wireshark

1. Открой дамп: появится список пакетов.
2. **Фильтры** в строке сверху сужают список:
   | Фильтр | Что показывает |
   |---|---|
   | `http` | только HTTP |
   | `dns` | DNS-запросы (данные могут быть в поддоменах) |
   | `tcp.port == 80` | трафик на порт 80 |
   | `frame contains "flag"` | пакеты со словом flag |
3. **Follow Stream** - основной приём: правой кнопкой по пакету -> *Follow -> TCP Stream*
   (или *HTTP Stream*). Покажет весь диалог клиента и сервера текстом, где обычно лежит флаг,
   файл или логин с паролем.
4. **File -> Export Objects -> HTTP** - сохранить переданные по HTTP файлы.

### Быстрая проверка из терминала

Часто флаг виден в `strings`, потому что текст в пакетах хранится как есть:

```bash
strings dump.pcap | grep -i flag
strings dump.pcap | grep -i -E 'flag|password|user|POST|GET'
```

Мощнее консольный `tshark`:

```bash
tshark -r dump.pcap -Y http                     # показать HTTP-пакеты (-Y = фильтр)
tshark -r dump.pcap -Y 'frame contains "flag"'  # пакеты со словом flag
tshark -r dump.pcap -Tfields -e http.request.full_uri   # все запрошенные URL
# вытащить тело конкретного TCP-потока (номер 0):
tshark -r dump.pcap -qz follow,tcp,ascii,0
```

💡 Данные в трафике часто закодированы (Base64 в заголовке, hex в теле). Найденную строку
раскодируй по главе 4 (`base64 -d`, `bytes.fromhex`).

🎯 **Тренировка 16.** Если есть `.pcap` (можно записать свой: `tcpdump -w my.pcap` несколько секунд),
открой его в Wireshark, примени фильтр `http`, сделай *Follow TCP Stream* и найди то же самое
из терминала через `strings my.pcap | grep`.

## 5.8. Аудио-стего (коротко)

Если дали `.wav`/`.mp3`, а метаданные и LSB пусты, секрет может быть **нарисован в спектрограмме**
(изображении частот). Открой файл в **Audacity** или **Sonic Visualiser**, включи спектрограмму:
иногда флаг виден прямо надписью. В WAV также встречается LSB-стего по сэмплам - его извлекают
скриптом. Если данные спрятаны именно через `steghide`, используй его.

## 5.9. Форензика/стего: "вижу X -> делаю Y"

| Что видишь | Скорее всего | Что делать |
|---|---|---|
| любой файл | - | `file`, `strings \| grep flag`, `xxd \| head` |
| картинка, ничего в strings | вложение или LSB | `binwalk -e`, затем `zsteg -a` |
| `.jpg`/`.wav`, binwalk/zsteg молчат | `steghide` (пароль) | `steghide extract -sf ...` |
| картинка открывается не целиком | занижены размеры PNG | `pngcheck -v`, правка байтов |
| есть метаданные / это фото | EXIF | `exiftool` или `getexif()` в Python |
| два файла "склеены" | хвост после маркера конца | `binwalk`, ручной carve по сигнатуре |
| `.pcap` / `.pcapng` | дамп трафика | Wireshark -> Follow TCP Stream; `strings`/`tshark` |
| `.wav`/`.mp3`, пусто везде | спектрограмма | Audacity/Sonic Visualiser -> спектр |
| в архиве/папке есть `.git` | история коммитов | `git log -p` / `git show` - флаг в удалённом коммите |

> Сначала прогоняй файл по базовому ритуалу, затем действуй по признакам: метаданные, вложения,
> LSB, `steghide`, битый PNG, дамп трафика. Многие задачи дают флаг уже на `strings | grep`.
> Следующая категория - Web.
