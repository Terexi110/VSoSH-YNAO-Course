# Глава 5. Форензика и стеганография

Две близкие категории про "спрятанное в файлах".

- **Форензика (Forensics)** - расследование: вытащить скрытые, удалённые или замаскированные данные
  из файлов, образов дисков и дампов трафика. Вопрос: "что здесь спрятано и как это достать?"
- **Стеганография (Stego)** - искусство прятать данные **внутри** другого файла (картинки, аудио)
  так, чтобы внешне ничего не было заметно. Вопрос: "где именно спрятан секрет?"

Разница простая: криптография **скрывает смысл** (видно, что что-то зашифровано), стеганография
**скрывает сам факт** передачи (выглядит как обычная картинка). На CTF эти категории решаются
набором утилит + уже знакомыми `strings`/`xxd`/Python.

---

## 5.1. Тот же ритуал, но глубже

Над любым файлом из этих категорий всегда начинай одинаково:

```bash
file   подозрительный            # что это на самом деле?
strings подозрительный | grep -i '{'   # флаг лежит открыто?
xxd    подозрительный | head     # магические байты, аномалии в начале
binwalk подозрительный           # нет ли ВНУТРИ других файлов?
exiftool подозрительный          # что в метаданных?
```

Эти пять команд закрывают бОльшую часть лёгких форензик-задач. Разберём каждую "неочевидную".

💡 Очень часто флаг находится **первой же командой** `strings файл | grep flag`. Не поленись - это
бесплатно и мгновенно.

💡 Если файл родом из Windows (дамп, документ) - строки бывают в UTF-16 и обычный `strings` их не
видит. Добавь `strings -e l файл | grep -i flag` (`-e l` = little-endian UTF-16).

## 5.2. Метаданные - `exiftool`

**Метаданные** - служебная информация внутри файла: кто автор, какой камерой снято, когда, где
(GPS!), комментарии, описание. Флаг часто прячут именно туда.

```bash
exiftool image.jpg          # вывести ВСЕ метаданные
exiftool image.jpg | grep -i -E 'flag|comment|gps|author|description'
```

На что смотреть: `Comment`, `Image Description`, `Artist`/`Author`, `Make`/`Model` (модель "камеры"
бывает подсказкой), `GPS Position` (координаты -> место -> подсказка/флаг), `Software`.

**Если `exiftool` недоступен - читаем EXIF на Python** (есть всегда, через Pillow):

```python
from PIL import Image
img = Image.open("image.jpg")
exif = img.getexif()
for tag_id, value in exif.items():
    print(hex(tag_id), value)     # 0x010e = ImageDescription, 0x0110 = Model, ...
# частые теги: 0x010e Описание, 0x0110 Модель, 0x013b Автор, 0x8298 Copyright
```

⚠️ Метаданные - не только у картинок. У PDF (`exiftool doc.pdf` -> Author, Keywords, Title), у
офисных документов, у аудио. Всегда проверяй.

🎯 **Тренировка 13.** На Python создай картинку и запиши ей в EXIF описание `flag{...}`
(`exif = img.getexif(); exif[0x010e] = "flag{meta}"; img.save("m.jpg", exif=exif)`), затем достань
его обратно через `getexif()`. Так ты поймёшь изнутри, как прячут и находят метаданные.

## 5.3. Склеенные и вложенные файлы - `binwalk` / `foremost`

Частый приём: к картинке в конец **дописан** архив или другой файл. Внешне - обычный PNG, но внутри
прячется zip с флагом. Картинка открывается (программа читает до маркера конца), а "хвост" не виден.

**Найти вложения - `binwalk`:**

```bash
binwalk image.png            # покажет найденные сигнатуры: Zip archive, PNG, gzip, ...
binwalk -e image.png         # -e = extract: сразу извлечь всё найденное в папку _image.png.extracted/
```

**Альтернатива - `foremost`** (вырезает файлы по сигнатурам):

```bash
foremost -i image.png -o out_dir   # извлечённое ляжет в out_dir/
```

**Как это работает руками (и как сделать без тулзов, на Python).** Каждый формат начинается со своей
сигнатуры (глава 2). Находим сигнатуру архива внутри файла и вырезаем "хвост":

```python
data = open("glued.png", "rb").read()
idx = data.find(b"PK\x03\x04")      # сигнатура ZIP-архива
print("ZIP начинается со смещения", idx)
open("carved.zip", "wb").write(data[idx:])   # вырезаем всё от сигнатуры до конца
# теперь: unzip carved.zip
```

💡 Вырезанный архив часто запаролен словарным паролем - ломается перебором (в образе есть `john`):
```bash
zip2john carved.zip > hash.txt && john hash.txt --wordlist=wordlist.txt
# john hash.txt --show  # показать найденный пароль; перебор без утилит - на zipfile (10-misc medium)
```

💡 Самый быстрый "детектор склейки": `strings image.png | grep flag`. Если флаг дописан текстом в
конец - увидишь сразу. Если нет - иди через `binwalk`.

🎯 **Тренировка 14.** Склей картинку и zip в терминале: `cat cover.png secret.zip > glued.png`.
Открой `glued.png` как картинку (открывается!), потом достань спрятанный zip тремя путями:
`binwalk -e`, ручным поиском `PK` в Python, и просто `unzip glued.png` (unzip умеет находить архив
в конце файла).

## 5.4. Стего в картинках: LSB

**LSB (Least Significant Bit)** - самый частый приём картинной стеганографии. Идея: младший бит
каждого цветового байта пикселя почти не влияет на цвет (глазу разницы нет), поэтому в эти младшие
биты можно "зашить" сообщение.

```
Пиксель R = 10110110 -> меняем последний бит на бит секрета -> 10110111
                   ^                                               ^
          почти не влияет на цвет                        но несёт 1 бит данных
```

**Готовые инструменты:**

```bash
zsteg image.png              # автоматически перебирает LSB-схемы для PNG/BMP - часто сразу флаг
zsteg -a image.png           # -a = все методы
```

`stegsolve` - графическая утилита: открываешь картинку и листаешь "битовые плоскости" (bit planes)
стрелками. Скрытая картинка/текст проявляется в одном из слоёв. Также умеет XOR каналов, разницу и
т.п. Незаменима, когда спрятана не строка, а **изображение**.

**Как достать LSB вручную на Python** (когда `zsteg` не берёт или хочешь понять суть):

```python
from PIL import Image
import numpy as np

img = Image.open("image.png").convert("RGB")
flat = np.array(img).flatten()          # все байты R,G,B подряд

# собираем младшие биты в байты
bits = ''.join(str(b & 1) for b in flat)
data = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits) - 7, 8))

# ищем читаемый кусок / флаг
import re
m = re.search(rb'flag\{[^}]+\}', data)
print(m.group() if m else data[:64])
```

⚠️ Нюансы, которые стоит перебрать, если "в лоб" не вышло: порядок каналов (RGB vs. по одному
каналу), какой бит (не только самый младший), порядок бит в байте, направление обхода (по строкам/
столбцам). Именно это и перебирает `zsteg -a` - поэтому с него и начинай.

🎯 **Тренировка 15.** На Python зашей `flag{...}` в младшие биты пикселей картинки (меняй
`flat[i] = (flat[i] & 0xFE) | bit`), сохрани PNG, потом достань сообщение обратно скриптом выше.
Сравни две картинки глазами - разницы не будет. Это и есть LSB.

## 5.5. Стего с паролем - `steghide`

`steghide` прячет данные в JPEG/BMP/WAV/AU, **защищая паролем**. Признак: дали `.jpg` или `.wav`,
где `binwalk`/`zsteg`/`strings` ничего не находят, - пробуй `steghide`.

```bash
steghide extract -sf image.jpg               # спросит пароль
steghide extract -sf image.jpg -p "пароль"   # если пароль известен/угадан
steghide info image.jpg                      # есть ли вообще вложение
```

💡 Пароль часто пустой (просто Enter) или лежит рядом - в названии файла, в метаданных, в тексте
условия. Если пароль неизвестен, но подозрение сильное - его перебирают утилитой `stegseek` по
словарю (есть в образе, работает офлайн):

```bash
stegseek image.jpg wordlist.txt      # быстрый перебор пароля по словарю
```

## 5.6. Фокусы со структурой файла (особенно PNG)

Иногда файл "битый" намеренно - и в этом весь смысл задачи.

- **Неверные размеры PNG.** В заголовке PNG зашиты ширина/высота. Если их занизили, часть картинки
  (с флагом) не отрисовывается. Лечится правкой байтов размеров в hex-редакторе или проверкой:
  ```bash
  pngcheck -v image.png        # покажет структуру чанков и ошибки
  ```
  ⚠️ После правки байтов размеров картинка начнёт ругаться на контрольную сумму (CRC). Чтобы всё же
  открыть её в Python: `from PIL import ImageFile; ImageFile.LOAD_TRUNCATED_IMAGES = True` (либо
  пересчитать CRC чанка IHDR - см. `hard.md`).
- **Данные после маркера конца.** У JPEG конец - байты `FF D9`, у PNG - чанк `IEND`. Всё, что после,
  - спрятанный "хвост" (см. п. 5.3).
- **Подменённое расширение.** `file` покажет настоящий тип; переименуй и открывай правильно.

💡 Общий принцип: открой файл в `xxd ... | less` и сравни его начало/конец с тем, как ДОЛЖЕН
выглядеть этот формат. Любая аномалия - это и есть задача.

## 5.7. Анализ трафика - дампы `.pcap` / `.pcapng`

Файлы `.pcap`/`.pcapng` - это **записанный сетевой трафик**. Открываются в **Wireshark** (GUI, есть
в образе). Задача обычно: найти переданный флаг/файл/пароль среди пакетов.

### Wireshark: что нажимать

1. Открой дамп -> увидишь список пакетов.
2. **Фильтры** (строка вверху) сужают выдачу:
   | Фильтр | Что показывает |
   |---|---|
   | `http` | только HTTP |
   | `dns` | DNS-запросы (часто прячут данные в поддоменах) |
   | `tcp.port == 80` | трафик на порт 80 |
   | `frame contains "flag"` | пакеты, где встречается слово flag |
3. **Follow Stream** - главный приём: правой кнопкой по пакету -> *Follow -> TCP Stream* (или *HTTP
   Stream*). Покажет весь диалог клиента и сервера целиком, как текст, - там обычно и лежит флаг,
   переданный файл или логин/пароль.
4. **File -> Export Objects -> HTTP** - вытащить переданные по HTTP файлы (картинки, архивы) на диск.

### Офлайн/быстро - из терминала

Самое простое - часто флаг виден обычным `strings`, ведь текст в пакетах лежит как есть:

```bash
strings dump.pcap | grep -i flag
strings dump.pcap | grep -i -E 'flag|password|user|POST|GET'
```

Мощнее - консольный Wireshark `tshark` (есть в образе):

```bash
tshark -r dump.pcap -Y http                     # показать HTTP-пакеты (-Y = фильтр)
tshark -r dump.pcap -Y 'frame contains "flag"'  # пакеты со словом flag
tshark -r dump.pcap -Tfields -e http.request.full_uri   # все запрошенные URL
# вытащить тело конкретного TCP-потока (номер 0):
tshark -r dump.pcap -qz follow,tcp,ascii,0
```

💡 Данные в трафике часто ещё и закодированы (Base64 в заголовке, hex в теле). Вытащил строку -
прогони через главу 4 (`base64 -d`, `bytes.fromhex`).

🎯 **Тренировка 16.** Если есть любой `.pcap` (можно записать свой: `tcpdump -w my.pcap` пару секунд),
открой его в Wireshark, примени фильтр `http`, сделай *Follow TCP Stream* на любом пакете и найди
то же самое из терминала через `strings my.pcap | grep`.

## 5.8. Аудио-стего (коротко)

Если дали `.wav`/`.mp3` и в метаданных/LSB пусто - секрет может быть "нарисован" в **спектрограмме**
(картинка частот звука). Открой файл в **Audacity** или **Sonic Visualiser** -> режим спектрограммы ->
иногда флаг виден прямо как надпись в спектре. Также у WAV бывает LSB-стего (тот же принцип, что с
картинками, но по сэмплам) - берётся `steghide`/скриптом.

## 5.9. Форензика/стего: "вижу X -> делаю Y"

| Что видишь | Скорее всего | Что делать |
|---|---|---|
| любой файл | - | `file`, `strings \| grep flag`, `xxd \| head` |
| картинка, ничего в strings | вложение или LSB | `binwalk -e`, затем `zsteg -a` |
| `.jpg`/`.wav`, binwalk/zsteg молчат | `steghide` (пароль) | `steghide extract -sf ...` |
| картинка открывается не целиком | занижены размеры PNG | `pngcheck -v`, правка байтов |
| есть метаданные / это фото | EXIF | `exiftool` или `getexif()` в Python |
| два файла "склеены" | хвост после маркера конца | `binwalk`, ручной carve по сигнатуре |
| `.pcap` / `.pcapng` | дамп трафика | Wireshark -> Follow TCP Stream; `strings`/`tshark` |
| `.wav`/`.mp3`, пусто везде | спектрограмма | Audacity/Sonic Visualiser -> спектр |
| в архиве/папке есть `.git` | история коммитов | `git log -p` / `git show` - флаг в удалённом коммите |

> Теперь любой подозрительный файл ты сначала гонишь по ритуалу, а потом действуешь по симптомам:
> метаданные, вложения, LSB, `steghide`, битый PNG, дамп трафика. Половина задач отдаёт флаг уже на
> `strings | grep` - с него и начинай, не выдумывая сложного. Следующая категория - Web.
