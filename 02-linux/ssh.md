# Глава 2. SSH: удалённая работа

SSH (Secure Shell) открывает командную строку на другой машине. На CTF он нужен в двух случаях: тебе дали логин с паролем (или ключ) от сервера, или надо забрать файлы и добраться до сервиса, который снаружи не виден. Краткая версия для сетевых задач лежит в [п. 7.7](../07-networking/medium.md), здесь то же самое подробнее.

## 2.S1. Подключение

```bash
ssh user@10.0.0.5                  # зайти под пользователем user (спросит пароль)
ssh -p 2222 user@10.0.0.5          # нестандартный порт (-p, маленькая буква)
ssh user@10.0.0.5 'cat /flag.txt'  # выполнить одну команду и сразу выйти
exit                               # выйти с сервера (или Ctrl + D)
```

Что происходит при первом подключении:

```text
The authenticity of host '10.0.0.5' can't be established.
ED25519 key fingerprint is SHA256:...
Are you sure you want to continue connecting (yes/no)?
```

Это отпечаток ключа **сервера**. Если организаторы дали отпечаток - сверь его, затем введи `yes` целиком (одной буквы `y` мало). Подтверждённые серверы запоминаются в `~/.ssh/known_hosts`.

⚠️ Пароль при вводе **не отображается**: ни звёздочек, ни точек. Так и должно быть, набирай и жми Enter.

⚠️ Ошибка `REMOTE HOST IDENTIFICATION HAS CHANGED` значит, что у адреса поменялся ключ (например, стенд пересоздали). На своём стенде удали старую запись и подключись заново:

```bash
ssh-keygen -R 10.0.0.5             # убрать адрес из known_hosts
```

🎯 **Тренировка S1.** Подключись к учебному серверу Bandit:

```bash
ssh bandit0@bandit.labs.overthewire.org -p 2220    # пароль первого уровня: bandit0
```

## 2.S2. Что делать после входа

Дальше это обычная оболочка, только на чужой машине. Сначала осмотрись:

```bash
whoami             # под кем я
id                 # группы пользователя
pwd; ls -la        # где я и что лежит (включая скрытое)
cat /etc/os-release
sudo -l            # что мне разрешено запускать через sudo
find / -name 'flag*' 2>/dev/null
```

На CTF флаг часто лежит в домашней папке, в `/opt`, `/var/www` или недоступен текущему пользователю, пока не найдёшь способ повысить права (см. [hard](hard.md)).

## 2.S3. Вход по ключу

Вместо пароля можно входить по **паре ключей**: приватный (секретный, остаётся у тебя) и публичный (кладётся на сервер).

Если тебе выдали готовый приватный ключ (`id_rsa`, `key.pem`):

```bash
chmod 600 key.pem                  # без этого ssh откажется: "UNPROTECTED PRIVATE KEY FILE"
ssh -i key.pem user@10.0.0.5       # -i = войти по этому ключу
```

Если ключ нужно создать самому:

```bash
ssh-keygen -t ed25519              # создаст ~/.ssh/id_ed25519 (приватный) и id_ed25519.pub (публичный)
ssh-copy-id user@10.0.0.5          # положить публичный ключ на сервер (один раз, по паролю)
ssh user@10.0.0.5                  # теперь пароль не нужен
```

Как это устроено вручную: публичный ключ - это одна строка в файле `~/.ssh/authorized_keys` **на сервере**.

```bash
mkdir -p ~/.ssh
echo 'ssh-ed25519 AAAA... me@pc' >> ~/.ssh/authorized_keys
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

⚠️ Права важны: если папка `~/.ssh` или файл ключа доступны всем, `sshd` молча игнорирует ключ, и вход по нему не работает.

⚠️ **Никогда не публикуй приватный ключ** (файл без `.pub`) и не присылай его в чат. Публичный (`.pub`) можно показывать свободно.

## 2.S4. Копирование файлов: scp, sftp, rsync

```bash
scp user@10.0.0.5:/flag.txt .              # скачать файл в текущую папку
scp data.bin user@10.0.0.5:/tmp/           # загрузить файл на сервер
scp -r user@10.0.0.5:/var/log ./logs       # целая папка (-r = рекурсивно)
scp -P 2222 user@10.0.0.5:/flag.txt .      # порт у scp - БОЛЬШАЯ -P
```

| Утилита | Когда использовать |
|---|---|
| `scp` | быстро скопировать один файл или папку |
| `sftp user@host` | интерактивный сеанс: `ls`, `cd`, `get файл`, `put файл`, `bye` |
| `rsync -av user@host:/dir/ ./dir/` | копировать много файлов и докачивать только изменившееся |

Если скопировать нужно только содержимое файла без записи на диск, используй вывод команды:

```bash
ssh user@10.0.0.5 'cat /var/log/auth.log' > auth.log   # файл окажется у тебя
```

## 2.S5. Файл настроек ~/.ssh/config

Чтобы не набирать длинную команду каждый раз, опиши сервер в `~/.ssh/config`:

```text
Host ctf
    HostName 10.0.0.5
    User user
    Port 2222
    IdentityFile ~/.ssh/key.pem
```

После этого:

```bash
ssh ctf
scp ctf:/flag.txt .
```

## 2.S6. Проброс портов (туннели)

🔺 Туннель позволяет достучаться до сервиса, который на сервере слушает только локально, или наоборот.

```bash
ssh -L 8080:127.0.0.1:3306 user@10.0.0.5   # мой :8080 -> порт 3306 внутри сервера
ssh -L 8080:127.0.0.1:80 -N user@10.0.0.5  # -N: ничего не выполнять, только держать туннель
ssh -R 9000:127.0.0.1:8000 user@10.0.0.5   # порт 9000 на сервере -> мой :8000
ssh -D 1080 -N user@10.0.0.5               # SOCKS-прокси на моём :1080
```

С `-L` (Local) порт открывается у тебя, а трафик уходит на сервер. После `-L 8080:127.0.0.1:80` открой в браузере `http://127.0.0.1:8080`: ты увидишь страницу, которую сервер считает своей локальной. Туннель живёт, пока работает команда `ssh`, остановить можно через `Ctrl + C`.

🔺 Если до цели можно добраться только через промежуточную машину, зайди через неё одной командой:

```bash
ssh -J user@gate user2@inner               # зайти на inner через gate
```

## 2.S7. Автоматизация и скрипты

```bash
ssh user@10.0.0.5 'ls /home'                    # одна команда
ssh user@10.0.0.5 'bash -s' < script.sh         # выполнить локальный скрипт на сервере
sshpass -p 'пароль' ssh user@10.0.0.5 'id'      # пароль в команде (если установлен sshpass)
```

⚠️ Пароль в командной строке попадает в историю (`history`) и список процессов. На тренировках допустимо, в реальной работе - нет.

Из Python (библиотека `paramiko`, если установлена):

```python
import paramiko

c = paramiko.SSHClient()
c.set_missing_host_key_policy(paramiko.AutoAddPolicy())   # не спрашивать про отпечаток
c.connect('10.0.0.5', port=22, username='user', password='secret')
stdin, stdout, stderr = c.exec_command('cat /flag.txt')
print(stdout.read().decode())
c.close()
```

## 2.S8. Свой SSH-сервер для тренировки

Чтобы потренироваться без чужих серверов, подними SSH у себя и зайди на `localhost`:

```bash
sudo apt install openssh-server    # установить сервер (Debian/Ubuntu/Kali)
sudo systemctl start ssh           # запустить (на некоторых системах служба называется sshd)
systemctl status ssh               # проверить, что работает
ssh localhost                      # войти на собственную машину
```

В WSL службу включают так же; если `systemctl` не работает - `sudo service ssh start`. Попробуй настроить вход по ключу (п. 2.S3) и скопировать файл через `scp` с одной папки в другую.

## 2.S9. Если не подключается

| Симптом | Причина и действие |
|---|---|
| `Connection refused` | на порту никто не слушает: проверь адрес, порт (`-p`), запущен ли сервис |
| `Connection timed out` | нет маршрута или порт закрыт фильтром: проверь `ping`, адрес и сеть |
| `Permission denied (publickey)` | сервер принимает только ключ: укажи `-i`, проверь `chmod 600` |
| `Permission denied, please try again` | неверный логин или пароль |
| `UNPROTECTED PRIVATE KEY FILE` | у ключа слишком широкие права: `chmod 600 ключ` |
| `Host key verification failed` | ключ сервера изменился: `ssh-keygen -R адрес` (только на своём стенде) |

Для диагностики добавь `-v` (`ssh -v user@host`; `-vv` и `-vvv` - подробнее): будет видно, какие ключи пробует клиент и на каком шаге вход рвётся.

## Шпаргалка

| Задача | Команда |
|---|---|
| войти | `ssh user@host` / `ssh -p PORT user@host` |
| войти по ключу | `chmod 600 key; ssh -i key user@host` |
| одна команда | `ssh user@host 'команда'` |
| скачать файл | `scp user@host:/путь/файл .` |
| загрузить файл | `scp файл user@host:/путь/` |
| создать ключ | `ssh-keygen -t ed25519` |
| туннель к локальному порту сервера | `ssh -L 8080:127.0.0.1:80 -N user@host` |
| забыл, что не так | `ssh -v user@host` |
