## 1. Массив и указатель - почти одно и то же

В большинстве выражений массив преобразуется в **указатель на первый элемент**.
Поэтому элементы можно читать двумя способами:

```c
#include <stdio.h>
int main(void) {
    char s[] = "flag";
    char *p = s;                        // p = адрес начала массива
    printf("%c%c\n", s[1], *(p + 1));   // s[1] и *(p+1) - одно и то же -> ll
    return 0;
}
```

💡 Правило чтения декомпилятора: `*(p + i)` - это просто `p[i]`. Ghidra часто пишет обращения к
строкам именно в виде `*(char *)(param_1 + i)` - читай как "i-й символ строки `param_1`".

## 2. Как лежит память и почему это важно

Локальные переменные часто лежат на **стеке**. Запись за границы массива - **переполнение буфера**:
она может повредить соседние данные или завершить программу аварийно.

```c
#include <stdio.h>
#include <string.h>
int main(void) {
    int  is_admin = 0;      // сосед буфера
    char buf[8];            // место ровно на 8 байт
    strcpy(buf, "AAAAAAAAAAAA");   // 12 'A' - 8 в buf, лишние 4 ушли в соседа
    printf("is_admin = %d\n", is_admin);   // уже не 0!
    if (is_admin) printf("flag{overflow_changed_me}\n");
    return 0;
}
```

Собрать без защиты стека и запустить:

```bash
gcc -fno-stack-protector -o prog prog.c && ./prog
# is_admin = 1094795585
# flag{overflow_changed_me}
```

`1094795585` - это `0x41414141`: четыре байта `'A'` вместо нуля. Ненулевой `is_admin`
пропускает проверку.

⚠️ Это лишь возможный результат: выход за границы - **неопределённое поведение**. Раскладка памяти,
оптимизации и защита могут изменить результат или вызвать падение. Stack protector зависит от настроек
сборки; здесь его отключили через `-fno-stack-protector`. `strcpy` копирует ещё и завершающий ноль.

🔺 В pwn также затирают **адрес возврата функции**, чтобы изменить ход выполнения
(`09-pwn/hard.md`). Общая причина та же: запись выходит за границы буфера.

## 3. Опасные функции (их ищут в реверсе и pwn)

Переполнение возможно, когда ввод читают **без проверки длины**:

```c
char buf[8];
gets(buf);              // ОПАСНО: читает сколько угодно, границы не знает
strcpy(buf, src);       // ОПАСНО: копирует src целиком, даже если не влезает
scanf("%s", buf);       // ОПАСНО: тот же %s без ограничения длины
```

Для `buf[8]` длину ограничивают `fgets(buf, sizeof(buf), stdin)` или `scanf("%7s", buf)`.
У `strncpy` есть ловушка: если источник не короче лимита, завершающий ноль не добавляется.
`gets` удалена из современного стандарта C.

💡 Маленький `char buf[...]` рядом с `gets`, `strcpy` или `scanf("%s")` - повод проверить границы.
Именно такие места ищут в `09-pwn`.

## 4. gcc vs g++ и немного C++

C++ близок к C, но не полностью с ним совместим. Здесь есть строки-объекты, потоки ввода-вывода
и классы. Расширение файлов - `.cpp`, компилятор - `g++`.

```cpp
#include <iostream>     // вместо stdio.h
#include <string>
int main() {
    std::string s = "flag";   // строка-объект, сама следит за длиной
    s += "{cpp}";                 // к строке можно прибавлять
    std::cout << s << std::endl;  // cout вместо printf, << "подаёт" данные -> flag{cpp}
    return 0;
}
```

```bash
g++ -o prog prog.cpp && ./prog     # -> flag{cpp}
```

`std::cout << x` печатает `x`; `std::endl` - перевод строки. Арифметика и типы - те же, что в C:

```cpp
#include <iostream>
int main() {
    int x = 21;
    std::cout << "flag{" << x * 2 << "}" << std::endl;   // -> flag{42}
    return 0;
}
```

🔺 В C++-бинарниках много служебного кода: конструкторы, деструкторы, вызовы
`std::__cxx11::basic_string...`. Следы `std::`, `__cxx`, `basic_string` в `strings` помогают
опознать C++. Ищи среди них сравнение ввода с эталоном.

## 5. Как исходник превращается в псевдокод

Один и тот же код в исходнике и в декомпиляторе выглядит по-разному. Полезно держать в голове
соответствия:

| В исходнике C | Что увидишь в Ghidra |
|---|---|
| `char buf[16]` | `char local_18 [16]` (имя по смещению на стеке) |
| имя переменной `pass` | `local_18`, `param_1`, `iVar1` (имена потеряны) |
| `s[i]` | `*(char *)(param_1 + i)` |
| `if (strcmp(a,b)==0)` | вызов `strcmp`, затем проверка результата на `0` |
| `for (i=0; i<n; i++)` | метка + условный переход назад (цикл) |
| строковый литерал `"s3cret"` | строка в секции данных, видна в Defined Strings |

```c
char pass[16];
scanf("%15s", pass);
if (strcmp(pass, "s3cret") == 0) printf("flag{ok}\n");   // пароль прямо в коде
```

Логика останется: ввод -> `strcmp` с `"s3cret"` -> печать флага при совпадении.
Имена могут пропасть, но строка `"s3cret"` часто видна даже через `strings`.

🎯 **Тренировка (hard).** Оберни фрагмент из п. 5 в `main`, добавь `stdio.h` и `string.h`, собери
(`gcc -o prog prog.c`). Найди пароль через `strings prog | grep -i s3cret` и введи его.
Затем открой `prog` в Ghidra (см. `08-reverse/ghidra.md`), найди `strcmp` и сравни псевдокод с исходником.
