# Глава 4. Криптография

Техник здесь немного, и они повторяются от задачи к задаче, так что криптографию реально довести
до автоматизма. Начнём с короткой теории: что именно ты ломаешь и зачем. Без неё крипто-задачи
кажутся магией. Глава длинная - но на муниципале крипта приносит больше всего баллов, так что время
на неё окупается.

---

## 4.1. Алиса, Боб и Ева - язык криптографии

Во всей литературе по крипте действующих лиц зовут одинаково - привыкай к этим именам, ты их
встретишь в любом условии и любом учебнике:

| Имя | Роль |
|---|---|
| **Алиса (Alice)** | отправитель, хочет послать сообщение |
| **Боб (Bob)** | получатель |
| **Ева (Eve)** | подслушивает канал (*eavesdropper*), пассивный злоумышленник |
| **Мэллори (Mallory)** | активный злоумышленник - может ещё и **менять** сообщения |

**Главная задача криптографии:** Алиса хочет передать сообщение Бобу через открытый канал (где
сидит Ева), так, чтобы Ева не смогла его прочитать. В CTF ты обычно играешь за Еву или Мэллори:
тебе дали перехваченный шифротекст (или уязвимую схему) - восстанови сообщение.

Криптография решает три задачи (запомни - это основа):

| Задача | По-русски | Вопрос, на который отвечает |
|---|---|---|
| **Confidentiality** | секретность | "не прочитает ли чужой?" |
| **Integrity** | целостность | "не изменили ли сообщение по дороге?" |
| **Authenticity** | подлинность | "точно ли это прислал тот, кто говорит?" |

💡 **Принцип Керкгоффса** - фундаментальное правило: стойкость шифра должна держаться **только на
секретности ключа**, а не на секретности алгоритма. Алгоритм можно считать известным всем (в CTF
его часто и дают открыто). Поэтому "спрятать логику" - не защита: задача как раз в том, чтобы, зная
алгоритм, восстановить данные или ключ.

## 4.2. Симметричное и асимметричное шифрование

Это деление - главный "водораздел" всей криптографии.

### Симметричное шифрование - один ключ на всё

Алиса и Боб используют **один и тот же секретный ключ** и для шифрования, и для расшифровки. Они
должны договориться о ключе **заранее**.

```
            ключ K                         ключ K
             |                              |
  сообщение -v-> [шифр] -> шифротекст -> [расшифр] -v-> сообщение
     (Алиса)                                      (Боб)
```

- + Быстро, подходит для больших объёмов данных.
- - Проблема: **как передать ключ** Бобу так, чтобы Ева его не перехватила? (проблема обмена ключами).
- Примеры: Цезарь, XOR, Виженер (слабые, учебные) и **AES** (сильный, современный стандарт).

### Асимметричное шифрование - пара ключей

У каждого участника **два** ключа, математически связанных:
- **открытый (public)** - его можно раздавать всем; им **шифруют** сообщение для тебя;
- **закрытый (private)** - хранится в секрете; только им можно **расшифровать**.

```
   открытый ключ Боба            закрытый ключ Боба
             |                          |
  сообщение -v-> [шифр] -> ... -> [расшифр] -v-> сообщение
    (Алиса шифрует                   (только Боб
     публичным ключом Боба)           может расшифровать)
```

- + Не нужно заранее передавать секрет: Алиса берёт **открытый** ключ Боба (он публичный) и шифрует.
  Расшифровать сможет только Боб своим закрытым. Проблема обмена ключами решена.
- - Медленно, подходит только для коротких данных.
- Пример: **RSA** (его и разбираем в п. 4.13).

### Гибридные схемы - как на самом деле работает интернет

На практике совмещают: **асимметрикой передают маленький симметричный ключ сессии**, а дальше весь
трафик шифруют быстрой симметрикой. Именно так устроен HTTPS: RSA/ECDH договариваются о ключе,
дальше данные идут под AES.

### Обмен ключами Диффи-Хеллмана (идея)

🔺 Отдельный трюк: Алиса и Боб могут получить **общий секрет**, обмениваясь данными по открытому
каналу, не передавая сам секрет. Аналогия: смешивание красок. У каждого есть общая "краска" и своя
тайная; они обмениваются смесями, и в конце у обоих получается один цвет, который Ева собрать не
может, хотя видела все пересылки. Математически за этим стоит сложность дискретного логарифма.
Для муниципала достаточно понимать идею.

### Цифровая подпись (идея)

Асимметрику можно применить "наоборот": **закрытым** ключом автор "подписывает" сообщение, а любой
проверяет подпись **открытым** ключом. Это даёт целостность и подлинность (задачи 2 и 3 из п. 4.1):
подделать подпись без закрытого ключа нельзя. На этом стоят JWT-токены, сертификаты HTTPS, подписи
GPG (с JWT встретимся в главе Web).

## 4.3. Распространённые алгоритмы и протоколы (обзор)

Чтобы не путаться в названиях, которые сыпятся в условиях. Не нужно уметь их все ломать - нужно
понимать, что есть что.

| Название | Тип | Для чего | Встречается на CTF |
|---|---|---|---|
| **AES** | симметричный блочный шифр | стандарт шифрования данных | иногда - но ключ почти всегда дают |
| **RSA** | асимметричный | шифрование/подпись | **часто** (крипто-задачи) |
| **Diffie-Hellman (DH)** | обмен ключами | договориться о ключе по открытому каналу | редко (🔺) |
| **ECC / ECDH** | асимметричный (эллиптические кривые) | то же, что RSA/DH, но компактнее | регион+ (🔺) |
| **MD5 / SHA-1 / SHA-256** | хеш-функции | отпечатки, пароли, целостность | часто (см. п. 4.5) |
| **TLS / HTTPS** | протокол | защищённый веб-трафик (гибрид) | как среда, не ломается |
| **SSH** | протокол | защищённый удалённый доступ | как инструмент |
| **PGP / GPG** | протокол/тулкит | шифрование почты и файлов | иногда в forensics/misc |

Что из этого реально приходится **ломать** на муниципале: RSA в простых случаях (п. 4.13), учебные
шифры (Цезарь, Виженер, XOR), кодировки и слабые применения хешей. AES, TLS, SSH, PGP - это то, что
стоит **узнавать по названию** и понимать назначение; целенаправленно их не взламывают (стойкие).

## 4.4. Три разные вещи: кодировка, хеш, шифр

Новички валят их в кучу. Разница принципиальная:

| | Кодировка | Хеш | Шифр |
|---|---|---|---|
| **Зачем** | представить данные иначе | получить "отпечаток" | скрыть данные |
| **Ключ нужен?** | нет | нет | да |
| **Обратимо?** | да, всегда | **нет** | да, если есть ключ |
| **Примеры** | Base64, hex, URL-encode | MD5, SHA-256 | Цезарь, XOR, AES, RSA |

Выводы, которые экономят время на туре:
- **Кодировку** просто раскодируй (ключ не нужен): `base64 -d`, `bytes.fromhex(...)`.
- **Хеш** расшифровать нельзя - его можно только **подобрать** (перебором/по словарю). См. п. 4.5.
- **Шифр** требует ключа или его подбора - этим займёмся начиная с п. 4.6.

💡 Как отличить по виду:
- только `0-9 a-f` и длина кратна 2 -> **hex**;
- буквы/цифры + `+ / =` на конце -> **Base64**;
- заглавные `A-Z` и `2-7` -> **Base32**;
- ровно 32/40/64 hex-символа -> скорее всего **хеш** (MD5/SHA1/SHA256).

## 4.5. Хеши - отпечатки данных

**Хеш-функция** превращает данные любой длины в "отпечаток" фиксированной длины. Свойства:

1. **Детерминированность:** один и тот же вход -> всегда один и тот же хеш.
2. **Лавинный эффект:** меняешь один бит входа -> хеш меняется целиком.
3. **Односторонность:** по хешу **нельзя** восстановить вход (нет обратной функции).
4. **Стойкость к коллизиям:** трудно найти два разных входа с одинаковым хешем.

**Где используются:** хранение паролей (хранят не пароль, а его хеш), проверка целостности файлов
(контрольные суммы), цифровые подписи.

### Опознать хеш по длине

| Длина (hex-символов) | Алгоритм |
|---|---|
| 32 | MD5 |
| 40 | SHA-1 |
| 64 | SHA-256 |
| 128 | SHA-512 |

```python
>>> import hashlib
>>> hashlib.md5(b"flag").hexdigest()      # 32 символа
'327a6c4304ad5938eaf0efb6cc3e53dc'
>>> hashlib.sha256(b"flag").hexdigest()   # 64 символа
'807d0fbcae7c4b20518d4d85664f6820aafdf936104122c5073e7744c46c4b87'
```

В терминале то же:
```bash
echo -n 'flag' | md5sum
echo -n 'flag' | sha256sum
md5sum файл            # контрольная сумма файла
```
⚠️ `echo -n` - без `-n` в конец добавится перевод строки, и хеш будет другим.

### "Взлом" хеша = подбор (его нельзя расшифровать)

Раз хеш необратим, единственный путь - **угадать вход**, посчитать его хеш и сравнить. Два способа:

**Словарная атака** (есть список вероятных паролей):

```python
import hashlib

target = "5f4dcc3b5aa765d61d8327deb882cf99"   # чей-то MD5
wordlist = ["123456", "password", "qwerty", "admin", "letmein"]

for w in wordlist:
    if hashlib.md5(w.encode()).hexdigest() == target:
        print("Пароль:", w)                      # -> password
        break
```

**Перебор** (короткие пароли из известного набора символов):

```python
import hashlib, itertools, string
target = "..."
chars = string.ascii_lowercase + string.digits
for length in range(1, 5):                        # длины 1..4
    for combo in itertools.product(chars, repeat=length):
        s = "".join(combo)
        if hashlib.md5(s.encode()).hexdigest() == target:
            print("Найдено:", s)
```

💡 Серьёзные инструменты для этого - **john** (John the Ripper) и **hashcat**; они есть в образе и
работают офлайн, перебирая миллионы вариантов. Но для коротких/словарных паролей хватает и Python.

💡 Если хеш "популярного" слова не колется перебором - его часто можно опознать: короткие известные
хеши совпадают у всех. На туре интернета нет, так что держи в голове: `md5("password")`,
`md5("admin")` и подобные ты при желании посчитаешь сам и сравнишь.

### Соль (salt) - почему не все хеши одинаково полезны

Чтобы одинаковые пароли не давали одинаковый хеш, к паролю добавляют **соль** - случайную строку:
`hash(salt + password)`. Тогда одинаковые пароли у разных людей дают разные хеши, и заранее
посчитанные таблицы (радужные) не помогают. Если в задаче виден `salt` - учитывай его при подборе.

### 🔺 Magic hashes - "магические" хеши (ловушка сравнения)

Очень любимый на CTF трюк на стыке крипты и веба. В PHP оператор `==` сравнивает "нестрого" и
пытается привести строки к числам. Если строка выглядит как `0e` и дальше **только цифры**, PHP
трактует её как число в экспоненциальной записи: `0e12345` = 0 x 10^12345 = **0**.

А теперь хитрость: существуют строки, чей MD5 имеет вид `0e` + только цифры. Для PHP **все такие
хеши равны нулю**, а значит равны **друг другу**:

```
md5("240610708") = 0e462097431906509019562988736854   <- 0e + одни цифры
md5("QNKCDZO")   = 0e830400451993494058024219903391   <- 0e + одни цифры

В PHP:  md5("240610708") == md5("QNKCDZO")   ->   0 == 0   ->   TRUE (!)
```

То есть два **разных** пароля проходят проверку как одинаковые. Так обходят сравнение хешей паролей
в уязвимом коде `if (md5($input) == $known_hash)`. Бывают и такие же "magic" хеши у SHA-1
(например, строка `aaroZmOk` даёт SHA-1 вида `0e66507...`).

Как это проверить/распознать на Python:

```python
import hashlib
h = hashlib.md5(b"240610708").hexdigest()
print(h)                                  # 0e462097431906509019562988736854
print(h[:2] == "0e" and h[2:].isdigit())  # True  -> это magic hash
```

💡 Если видишь в вебе сравнение хешей через `==` (PHP) - пробуй скормить известную magic-строку
(`240610708` для MD5). Это и есть эксплуатация "нестрогого сравнения" (с темой вернёмся в главе Web).

🎯 **Тренировка 7.** (а) Посчитай `md5` своего имени в Python и в терминале (`echo -n ... | md5sum`) -
убедись, что совпадает, и помни про `-n`. (б) Напиши словарный брутфорс: захешируй слово из списка,
"забудь" его и найди перебором по списку. (в) Проверь, что `md5("QNKCDZO")` действительно имеет вид
`0e` + цифры.

## 4.6. Кодировки: Base64 / Base32 / Base16

```python
import base64
base64.b64decode("ZmxhZ3tiNjR9")        # Base64 -> байты
base64.b32decode("MZXW6ZTFOIQQ====")     # Base32 -> байты (заглавные + 2-7)
base64.b16decode("666C6167")             # Base16 = hex (только заглавные!)
bytes.fromhex("666c6167")                # hex в любом регистре
```

⚠️ Частые грабли: у Base64 длина должна быть кратна 4 - не хватает, добивается знаком `=`
(*padding*). Если ругается на padding, допиши `=` до кратности 4:
```python
import base64
s = "ZmxhZ3tiNjR9"
base64.b64decode(s + "=" * (-len(s) % 4))   # сами добиваем padding
```

💡 Кодировки часто **вложены**: Base64 внутри Base64, hex внутри Base64. Декодируй слоями, пока не
покажется осмысленный текст или магические байты файла.

🎯 **Тренировка 8.** Закодируй флаг дважды и расшифруй обратно по слоям:
```python
import base64
x = base64.b64encode(base64.b64encode(b"flag{layers}"))
print(x)                                       # двойной Base64
print(base64.b64decode(base64.b64decode(x)))   # снимаем два слоя
```

## 4.7. Атбаш и зеркальные алфавиты

**Атбаш** - замена буквы на "зеркальную": первая <-> последняя, вторая <-> предпоследняя. Ключа нет,
расшифровка = шифровке.

```python
import string
low = string.ascii_lowercase
def atbash(s):
    out = ""
    for c in s:
        if c in low:
            out += low[25 - low.index(c)]   # зеркалим: a<->z, b<->y, ...
        else:
            out += c
    return out

print(atbash("svool"))   # -> hello
```

💡 Для кириллицы - тот же приём с русским алфавитом (`"абвгдежзийклмнопрстуфхцчшщъыьэюя"` и
`31 - index` (алфавит из 32 букв, индексы 0..31)). Атбаш - частный случай шифра замены.

## 4.8. Цезарь / ROT - сдвиг алфавита

Каждая буква сдвигается на фиксированное число позиций. Ключей всего 25 (латиница) или 31
(кириллица) - поэтому **ломается полным перебором сдвигов**.

### Латиница - универсальный брутфорс

```python
import string
low = string.ascii_lowercase

def caesar(s, shift):
    out = ""
    for c in s:
        if c.islower():
            out += low[(low.index(c) + shift) % 26]
        elif c.isupper():
            out += low[(low.index(c.lower()) + shift) % 26].upper()
        else:
            out += c            # пробелы, цифры, скобки - не трогаем
    return out

ct = "aol zljyla dvyk pz thaype"
for sh in range(26):            # перебираем ВСЕ сдвиги
    print(sh, caesar(ct, -sh))  # минус - расшифровка
```

Среди 26 строк глазами находишь осмысленную - при `sh = 7` получится
`the secret word is matrix`. Это и есть ответ.

💡 **ROT13** - Цезарь со сдвигом 13; он сам себе обратный (`caesar(s, 13)` туда и обратно).

### Кириллица - то же самое на русском алфавите

⚠️ Готовые ROT почти всегда латинские, а на олимпиаде текст часто **русский**. Поэтому свой
кириллический Цезарь надо уметь писать по памяти:

```python
A = "абвгдежзийклмнопрстуфхцчшщъыьэюя"   # 32 буквы (обычно без ё)

def caesar_ru(s, shift):
    out = ""
    for c in s:
        cl = c.lower()
        if cl in A:
            nc = A[(A.index(cl) + shift) % 32]
            out += nc.upper() if c.isupper() else nc
        else:
            out += c
    return out

ct = "пргь цфхдчет фуй пузхнпус"
for sh in range(32):
    print(sh, caesar_ru(ct, -sh))         # при sh=5 -> "ключ спрятан под ковриком"
```

🎯 **Тренировка 9.** Зашифруй русскую фразу `caesar_ru(фраза, 11)`, затем, НЕ подглядывая в сдвиг,
восстанови её перебором всех 32 вариантов. Научись быстро находить осмысленную строку глазами.

## 4.9. Частотный анализ и шифр простой замены

🔺 Если это не Цезарь, а **произвольная замена** (каждая буква заменена на свою, единого сдвига нет),
перебором 32 сдвигов не возьмёшь. Тогда помогает **частотный анализ**: в русском тексте чаще всего
встречаются "о, е, а, и, н, т", в английском - "e, t, a, o". Самая частая буква шифра скорее всего
соответствует самой частой букве языка.

```python
from collections import Counter
ct = "...зашифрованный текст..."
freq = Counter(c for c in ct if c.isalpha())
print(freq.most_common())    # самые частые символы шифра - сверху
```

Дальше - ручная работа: подставляешь частые буквы, угадываешь короткие слова, достраиваешь
остальное. На муниципале чаще обходятся Цезарем; замену с частотным анализом держи "на вырост".

## 4.10. Виженер - Цезарь с ключом-словом

Каждая буква сдвигается на свою величину, заданную **буквой ключа** (ключ повторяется по кругу).
Если ключ известен - расшифровка прямая: вычитаем сдвиг каждой буквы ключа.

```python
A = "абвгдежзийклмнопрстуфхцчшщъыьэюя"   # 32 буквы

def vigenere_ru(s, key, decrypt=False):
    key = key.lower()                      # ключ мог прийти с заглавной - иначе ValueError
    out = ""
    ki = 0                                 # отдельный счётчик - только по буквам
    for c in s:
        cl = c.lower()
        if cl in A:
            k = A.index(key[ki % len(key)])
            ki += 1
            shift = -k if decrypt else k    # расшифровка - вычитаем
            nc = A[(A.index(cl) + shift) % 32]
            out += nc.upper() if c.isupper() else nc
        else:
            out += c                        # пробелы ключ НЕ сдвигают
    return out

ct = "тапшл йтеьуэнс ып юлнгрфар"
print(vigenere_ru(ct, "тополь", decrypt=True))   # -> "атака начнется на рассвете"
```

⚠️ Главная ошибка - двигать счётчик ключа на пробелах и знаках. Счётчик `ki` увеличивается
**только на буквах**, иначе всё "поедет".

💡 Откуда берётся ключ? Его либо дают, либо прячут рядом (в названии задачи, в картинке, в
метаданных). Если ключа нет совсем - это криптоанализ Виженера (метод Касиски), на муниципале
почти не нужен.

## 4.11. XOR - одиночный и повторяющийся ключ

### Однобайтовый ключ - перебор 256 вариантов

Весь текст поксорен одним и тем же байтом. Ключей всего 256 - перебираем все и ищем тот, где
получается читаемый текст (или появляется `flag{`):

```python
ct = bytes.fromhex("2a2721...")             # шифротекст в байтах
for k in range(256):                        # перебор всех 256 ключей
    pt = bytes(b ^ k for b in ct)
    if b"flag" in pt:                        # фильтр по признаку флага
        print(k, pt)
```

💡 Фильтр `if b"flag" in pt` отсеивает мусор автоматически - не нужно глазами смотреть 256 строк.
Если формат флага другой - меняй признак (например, `if pt.isascii() and b"{" in pt`).

### Повторяющийся ключ + известный кусок текста (криб)

🔺 Ключ - короткое слово, повторяющееся по кругу. Если мы **знаем начало** открытого текста (а мы его
знаем - все флаги начинаются с `flag{`!), ключ восстанавливается мгновенно по свойству XOR:
`ключ = шифротекст ^ открытый текст`.

```python
ct = bytes.fromhex("2d29382c3e217b37067a3606252a2d14262b32352d7b38")

crib = b"flag{"                              # то, с чего ТОЧНО начинается текст
key_start = bytes(ct[i] ^ crib[i] for i in range(len(crib)))
print(key_start)                             # -> b'KEYKE'  => ключ "KEY" длины 3

key = b"KEY"
pt = bytes(ct[i] ^ key[i % len(key)] for i in range(len(ct)))
print(pt)                                    # -> b'flag{x0r_1s_not_crypt0}'
```

Логика восстановления:
1. XOR'им первые байты шифротекста с известным `flag{` - получаем начало ключа (`KEYKE`).
2. Видим, что оно периодично -> настоящий ключ короткий (`KEY`).
3. Применяем найденный ключ ко всему шифротексту.

🎯 **Тренировка 10.** Зашифруй `flag{...}` повторяющимся ключом, "забудь" ключ и восстанови его по
крибу `flag{`. Это одна из самых частых XOR-задач.

## 4.12. Главный навык: писать дешифратор к самодельному шифру

На муниципале крипто-задачу часто дают **как в реверсе**: вот скрипт (или функция на Python/C++),
который что-то шифрует, вот результат - верни исходник. Это ключевой навык курса: **прочитать
алгоритм шифрования и написать обратный**.

### Правило обращения

> **Чтобы расшифровать - выполни обратные операции в обратном порядке.**

Как снимаешь одежду в порядке, обратном тому, как надевал: последняя операция шифрования снимается
первой.

**Таблица обратных операций** (выучить!):

| Операция шифрования | Обратная при расшифровке |
|---|---|
| `x ^ k` (XOR) | `x ^ k` - **та же самая** (XOR сам себе обратный) |
| `x + k` (по модулю 256) | `x - k` |
| `x - k` | `x + k` |
| сдвиг бит влево `ROL n`: `((x << n)\|(x >> (8-n))) & 0xFF` | сдвиг вправо `ROR n`: `((x >> n)\|(x << (8-n))) & 0xFF` |
| замена по таблице `T[x]` | обратная таблица `T_inv` (где `T_inv[T[x]] = x`) |
| реверс последовательности | реверс последовательности |

⚠️ `& 0xFF` после `+`, `-`, сдвигов обязателен - он оставляет только младший байт (эмулирует
8-битное переполнение, как в C/C++). Без него числа "уедут" за пределы байта.

### Разбор по шагам - самодельный байтовый шифр

Допустим, в задаче дана такая функция шифрования (типичная "усложнёнка" с XOR, сложением, сдвигом
и **состоянием**, зависящим от шифротекста):

```python
def encrypt(data, key):
    out = []
    state = 0x3F                              # начальное состояние
    for i, b in enumerate(data):
        x = b ^ key[i % len(key)]             # 1) XOR с ключом
        x = (x + 0x11) & 0xFF                 # 2) прибавили 0x11
        x = ((x << 3) | (x >> 5)) & 0xFF      # 3) циклический сдвиг влево на 3 (ROL 3)
        x ^= state                            # 4) XOR с состоянием
        state = (state + x) & 0xFF            # 5) состояние меняется от ШИФРОБАЙТА x
        out.append(x)
    return bytes(out)
```

Пишем расшифровщик. Идём по шифробайтам; операции 4->3->2->1 обращаем в обратном порядке. Хитрость:
`state` на шаге 5 зависит от **шифробайта `x`**, а он у нас на руках - значит состояние можно честно
пересчитывать на ходу.

```python
def decrypt(data, key):
    out = []
    state = 0x3F                              # то же начальное состояние
    for i, x in enumerate(data):              # x - очередной ШИФРОБАЙТ
        y = x ^ state                         # обратно шагу 4: сняли XOR с состоянием
        y = ((y >> 3) | (y << 5)) & 0xFF      # обратно шагу 3: ROR 3 вместо ROL 3
        y = (y - 0x11) & 0xFF                 # обратно шагу 2: вычли 0x11
        b = y ^ key[i % len(key)]             # обратно шагу 1: сняли XOR с ключом
        state = (state + x) & 0xFF            # шаг 5: пересчёт состояния (от x, он известен)
        out.append(b)
    return bytes(out)

enc = bytes.fromhex("0ece83af8795d1b0ab0fdf62ec493b0ce9f2d5839f9b46ac488048d1")
print(decrypt(enc, b"s3cr3t"))                # -> b'flag{cust0m_c1ph3r_r3v3rs3d}'
```

Порядок рассуждения, который работает всегда:
1. Выпиши операции шифрования по шагам и **пронумеруй** их.
2. Для каждой найди обратную по таблице выше.
3. Расшифровщик делает обратные операции в **обратном порядке** (последняя -> первая).
4. Если есть "состояние", проверь, от чего оно зависит: от шифротекста - его можно пересчитывать при
   расшифровке; от открытого текста - считай его по мере восстановления байтов.

### А если шифратор на C/C++?

Логика та же - просто другой синтаксис. Типичная "усложнёнка" выглядит так:

```cpp
uint8_t step(uint8_t x, uint8_t k) {
    x ^= k;                         // XOR с ключом
    x = x + 0x19;                   // сложение (uint8_t сам обрежет до байта)
    return (x >> 2) | (x << 6);     // циклический сдвиг (ROR 2 для 8 бит)
}
```

Переписываешь на Python и **обращаешь**: `(x >> 2)|(x << 6)` для байта - это ROR 2, обратное ему
ROL 2 = `(x << 2)|(x >> 6)`; затем `- 0x19`; затем `^ k`. Тип `uint8_t` в C - это и есть наше
`& 0xFF` в Python.

💡 Если в C-коде стоит проверка `if (result[i] != table[i]) return false;` - значит `table` это и
есть зашифрованный правильный ответ. Тогда расшифровка - восстановить вход, дающий `table`. Можно
даже не выводить формулу обратной операции, а **подобрать каждый байт перебором** (все 256 значений):

```python
table = [0x21, 0x8d, 0x0b, ...]    # "эталон" из C-кода
key   = [0x41, 0x13, 0x77, ...]
def step(x, k):
    x ^= k; x = (x + 0x19) & 0xFF
    return ((x >> 2) | (x << 6)) & 0xFF

flag = []
for i in range(len(table)):
    for ch in range(256):           # перебираем все варианты входного байта
        if step(ch, key[i]) == table[i]:
            flag.append(ch); break
print(bytes(flag))
```

Этот "перебор каждого байта" - спасательный круг, когда лень/сложно выводить обратную формулу.
Работает, пока каждый байт шифруется независимо.

🎯 **Тренировка 11 (главная в крипте).** Напиши свою функцию `encrypt` из 3-4 операций (XOR +
сложение + сдвиг), зашифруй ей `flag{...}`, запиши результат в hex и **забудь исходник**. На
следующий день по одному только `encrypt` напиши `decrypt` и проверь, что вернулся флаг. Повтори с
разными наборами операций, добавь "состояние". Это именно тот навык, что приносит баллы в крипте.

## 4.13. RSA "на пальцах"

RSA пугает, но для CTF нужно знать совсем немного. Это асимметричный шифр (см. п. 4.2) с открытым и
закрытым ключом.

**Обозначения** (запомни - ими описывают любую RSA-задачу):

| Буква | Что это |
|---|---|
| `p`, `q` | два больших простых числа (секрет) |
| `n = p*q` | модуль (открыт, его все видят) |
| `e` | открытая экспонента, почти всегда `65537` |
| `phi = (p-1)*(q-1)` | функция Эйлера (нужна, чтобы найти `d`) |
| `d` | закрытая экспонента (секрет), `d = e^-1 mod phi` |
| `m` | сообщение (число) - то, что ищем |
| `c` | шифротекст (число), `c = m^e mod n` |

**Шифрование:** `c = pow(m, e, n)`. **Расшифровка:** `m = pow(c, d, n)`.

Весь вопрос - как получить `d`. А для этого нужно разложить `n` на `p` и `q`. Если это удалось -
дальше всё в 5 строк.

### Случай 1: даны `p` и `q` (или `n` маленькое)

```python
p = 61; q = 53                       # простые множители
e = 17
c = 2557
n = p * q                            # 3233
phi = (p - 1) * (q - 1)              # 3120
d = pow(e, -1, phi)                  # обратный элемент: d = e^(-1) mod phi
m = pow(c, d, n)                     # 42  - это и есть сообщение (число)
print(m)
```

💡 `pow(e, -1, phi)` в современном Python сразу считает **обратный по модулю** - раньше для этого
писали расширенный алгоритм Евклида, теперь одна функция. Это и есть вся "магия" получения `d`.

Превратить число `m` в текст флага:
```python
print(m.to_bytes((m.bit_length() + 7) // 8, "big"))   # число -> байты -> текст
```

💡 **Разложить маленькое `n` без Python - командой `factor`** (есть в Linux из коробки, работает
офлайн и мгновенно для небольших `n`, даже когда `p` и `q` далеко друг от друга и Ферма не берёт):
```bash
factor 3233      # -> 3233: 53 61
```
Если множителей три (`n = p*q*r`), то `phi = (p-1)(q-1)(r-1)`, а всё остальное работает так же.

### Случай 2: `p` и `q` очень близки -> факторизация Ферма

🔺 Классическая CTF-уязвимость: `p` и `q` выбрали **рядом** друг с другом (например, `q` - следующее
простое после `p`). Тогда `n` раскладывается за миллисекунды методом Ферма: ищем `n = a^2 - b^2`,
начиная с `a = округлённый вверх корень из n` и увеличивая `a`, пока `a^2 - n` не станет точным квадратом.

```python
import math

n = 1000000000000000000000000000156000000000000000000000000005643
e = 65537
c = 149103818650793714775999906680396769330332263560633309632451

a = math.isqrt(n)                    # целочисленный корень из n
if a * a < n:
    a += 1
while True:
    b2 = a * a - n
    b = math.isqrt(b2)
    if b * b == b2:                  # нашли точный квадрат -> разложили n
        p, q = a - b, a + b
        break
    a += 1

phi = (p - 1) * (q - 1)
d = pow(e, -1, phi)
m = pow(c, d, n)
print(m.to_bytes((m.bit_length() + 7) // 8, "big"))   # -> b'flag{cl0se_pr1mes_die}'
```

**Как распознать на туре:** дали скрипт генерации ключей и видно, что `q` берётся недалеко от `p`
(`q = nextprime(p + небольшое)`, `q = p + 2` и т.п.) - сигнал "ломать Фермой". Чем ближе `p` и `q`,
тем быстрее метод.

🔺 Другие "школьные" слабости RSA (общий модуль, маленькое `e` без паддинга, атака Винера) - это
уже уровень региона и выше. На муниципале достаточно уверенно делать два случая выше.

🎯 **Тренировка 12.** Сгенерируй свой маленький RSA: возьми два простых рядом (например, около 10^15),
посчитай `n, phi, d`, зашифруй `flag{...}` в число `c`. Потом по `n, e, c` восстанови флаг Фермой.
Прогоняй, пока схема "разложил n -> нашёл d -> `pow(c,d,n)`" не станет очевидной.

## 4.14. OpenSSL: крипта из командной строки

`openssl` - "швейцарский нож" прикладной крипты: посчитать хеш, расшифровать AES, прочитать
RSA-ключ. Пригодится, когда дали не учебные числа, а настоящий файл (`.enc`, `.pem`). Всё это есть и
в Python, но для разовой операции `openssl` быстрее.

**Хеши** (то же, что `hashlib`, но одной строкой):

```bash
echo -n "flag" | openssl dgst -sha256     # SHA-256 строки (-n = без перевода строки в конце!)
openssl dgst -md5 file.bin                 # MD5 файла
```

**Симметричное шифрование (AES).** Частый случай: дан файл `secret.enc` и пароль, надо расшифровать:

```bash
echo "secret text" | openssl enc -aes-256-cbc -pbkdf2 -base64 -pass pass:hunter2   # зашифровать
openssl enc -d -aes-256-cbc -pbkdf2 -base64 -pass pass:hunter2 -in secret.enc       # -d = расшифровать
```

⚠️ Параметры при расшифровке должны совпасть с теми, чем шифровали: тот же шифр (`-aes-256-cbc`), тот
же вид вывода (`-base64`, если данные не бинарные) и обязательно `-pbkdf2`, если файл делали
современным openssl. Не совпал один флаг - получишь `bad decrypt`.

**RSA-ключи.** Дали файл ключа (`key.pem`) - вытащи из него числа:

```bash
openssl rsa -in key.pem -noout -text        # показать n (modulus), e, d, p, q читаемо
openssl rsa -pubin -in pub.pem -noout -text  # то же для открытого ключа (-pubin)
```

Дальше `n, e, (d)` переносишь в Python и работаешь как в п. 4.13 (`pow(c, d, n)`); а если ключ только
открытый и `n` небольшое - раскладываешь `n` на `p, q` (Ферма или `factor`, п. 4.13).

**Сертификаты** (реже, но бывает):

```bash
openssl x509 -in cert.pem -noout -text       # что внутри сертификата (кому выдан, даты, ключ)
```

💡 `openssl` хорош для разовых операций над настоящими файлами. Где нужна логика (перебор, цикл,
нестандартный формат) - бери Python из п. 4.11-4.13. Для простого Base64 проще `base64 -d`, чем
openssl. Попробуй сам: зашифруй строку `openssl enc -aes-256-cbc -pbkdf2 -base64 -pass pass:ТВОЙ`,
сохрани вывод и расшифруй обратно, пока набор флагов не уляжется в голове.

## 4.15. Крипта: "вижу X -> делаю Y"

| Что видишь | Скорее всего | Что делать |
|---|---|---|
| только `0-9 a-f`, длина чётная | hex | `bytes.fromhex(...)` |
| буквы/цифры и `+ / =` | Base64 | `base64.b64decode(...)` |
| заглавные `A-Z` и `2-7` | Base32 | `base64.b32decode(...)` |
| ровно 32/40/64 hex-символа | хеш MD5/SHA1/SHA256 | не расшифровать - подбор по словарю/перебором |
| хеш вида `0e` + одни цифры, рядом PHP `==` | magic hash | подставить magic-строку (`240610708`) |
| текст из букв, пробелы на местах слов | Цезарь/замена | перебор сдвигов, частотный анализ |
| текст + дано слово-ключ | Виженер | `vigenere(..., decrypt=True)` |
| дан hex/байты без структуры | XOR | перебор 256 ключей или криб `flag{` |
| дан **скрипт/функция шифрования** | самодельный шифр | написать обратную функцию (п. 4.12) |
| даны `n, e, c` | RSA | разложить `n` (Ферма/`factor`), найти `d`, `pow(c,d,n)` |
| дан файл `.pem` (ключ) | RSA-ключ | `openssl rsa -in k.pem -noout -text` -> числа в Python (п. 4.14) |
| дан `.enc` + пароль | AES и т.п. | `openssl enc -d -aes-256-cbc -pbkdf2 ...` (п. 4.14) |
| точки и тире `. - /` | азбука Морзе | по таблице Морзе -> буквы |
| пары цифр 11-55 | квадрат Полибия (5x5, I=J) | по таблице координат |
| символы `+ - < > [ ] . ,` | Brainfuck | интерпретатор (см. `10-misc/hard.md`) |

> Глава была большая, но и отдача большая. Главное, что осталось в руках: читать чужой шифр и писать
> к нему обратную функцию, ломать Цезаря и XOR перебором, снимать Виженер по ключу, добивать RSA,
> когда простые близки или даны напрямую. Остальное - узнавание по виду плюс таблица в конце. Те же
> приёмы пригодятся и в форензике: там флаг тоже спрятан, только внутри файла.
