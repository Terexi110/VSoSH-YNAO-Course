# Глава 9. Pwn: знакомство

**Pwn** (от «own» — захватить) — эксплуатация ошибок программы через специально подобранный ввод.
На муниципальном этапе встречаются упрощённые задачи, на региональном — полноценные.
Здесь разберём основные идеи, без ROP и обхода защит.

## 9.1. Память и стек

В **стеке** хранятся локальные данные функции и служебные значения, в том числе **адрес возврата**:
куда перейти после завершения функции. Упрощённая схема для `buf[8]`:

```
   [ buf (8 байт) ][ другие переменные ][ адрес возврата ]
    ^
    сюда программа кладёт твой ввод
```

Данные могут лежать рядом, но точное расположение и промежутки зависят от компилятора.

## 9.2. Переполнение буфера (Buffer Overflow)

Если ввод длиннее буфера, а проверки длины нет, лишние байты перезаписывают соседнюю память:

```c
char buf[8];
gets(buf);          // gets НЕ проверяет длину - читает сколько угодно
```

💡 `gets()` убрали из стандарта C из-за её опасности. Она, `strcpy` и `scanf("%s")` в коде или
выводе `strings` — повод проверить, ограничена ли длина ввода.

Переполнение позволяет:

1. **Изменить соседнюю переменную.** Если сразу после `buf` лежит `int is_admin = 0`, следующие
   байты могут сделать его ненулевым и дать права администратора:
   ```
   ввод: "AAAAAAAA" + "\x01"  ->  buf заполнен, следующий байт лёг в is_admin
   ```
2. **Подменить адрес возврата.** Дойдя до него, можно записать адрес скрытой функции `win()`,
   печатающей флаг. При возврате программа перейдёт в неё:

```
   [ buf ][ ... ][ адрес возврата ]
    AAAAAAAA....  адрес функции win()   <- программа "вернётся" в win()
```

Признаки такой задачи: бинарник, адрес `IP:ПОРТ`, неограниченный ввод и подозрительная функция
`win`, `secret` или вызов `system`, до которых обычное выполнение не доходит. Ввод с непечатными
байтами адреса отправляют скриптом через `socket` или `pwntools` (глава 7).

## 9.3. Переполнение целого (Integer Overflow)

Целые числа имеют ограниченный размер. Беззнаковое значение при переполнении «оборачивается»,
как одометр с 9999 на 0000:

```c
uint8_t x = 255;
x = x + 1;        // не 256, а 0 (байт вмещает только 0..255)
```

Если вычисленный размер `len` переполнится и станет маленьким, проверка `if (len <= 100) allow();`
может пропустить слишком большой ввод. Похожая ошибка бывает при расчёте стоимости: произведение
цены и количества оборачивается в малое значение, иногда в `0`. Отрицательные значения тоже могут
обходить неудачные проверки, но переполнение знаковых чисел в C не гарантирует оборачивания.

Это та же арифметика по модулю, что `& 0xFF` в главе 4.

## 9.4. Что делать на туре

- Опознать задачу: бинарник и порт, неограниченный ввод, скрытая функция.
- Найти **смещение** до нужной переменной или адреса возврата по коду/Ghidra (п. 8.4).
  Одного размера буфера может быть недостаточно: между данными бывают промежутки.
- Собрать `b"A" * N + нужные_байты` и отправить скриптом из главы 7.
- ROP и обход защит (🔺🔺) изучать отдельно; здесь достаточно простого переполнения.
