# Глава 9. Pwn - ознакомительно

**Pwn** (от "own" - захватить) - задачи на эксплуатацию ошибок в программах: заставить программу
делать то, что не задумано, обычно через хитрый ввод. Это самая технически сложная категория, и на
муниципале в полном объёме её почти не бывает. Но понимать идею нужно - иногда встречается
упрощённый вариант, а на регионе это уже полноценная тема. Здесь - только концепции.

---

## 9.1. Как устроена память программы (минимум)

Когда программа работает, её данные лежат в памяти. Для pwn важен **стек** - область, куда
складываются локальные переменные функции и служебные данные, включая **адрес возврата** (куда
вернуться, когда функция закончится).

Упрощённо, при вызове функции с массивом `buf[8]` стек выглядит так:

```
   [ buf (8 байт) ][ другие переменные ][ адрес возврата ]
    ^
    сюда программа кладёт твой ввод
```

Ключевая идея: переменные лежат **рядом**, впритык друг к другу.

---

## 9.2. Переполнение буфера (Buffer Overflow)

Если программа читает ввод в буфер фиксированного размера **без проверки длины**, а ты вводишь
больше - лишние байты "вылезут" за буфер и затрут то, что лежит дальше в памяти.

**Уязвимый код** (классика):
```c
char buf[8];
gets(buf);          // gets НЕ проверяет длину - читает сколько угодно
```

💡 `gets()` настолько опасна, что её **убрали из стандарта языка C**. Поэтому её наличие в коде или
в `strings` бинарника - самый жирный маркер pwn-задачи (так же палевны `strcpy`, `scanf("%s")`).

Что можно сделать слишком длинным вводом:

1. **Затереть соседнюю переменную.** Если рядом лежит `int is_admin = 0`, и ты вводишь 8 байт для
   `buf` + ещё байты - они перезапишут `is_admin`. Было 0 (не админ) -> стало ненулевым (админ).
   ```
   ввод: "AAAAAAAA" + "\x01"  ->  buf заполнен, следующий байт лёг в is_admin
   ```
2. **Перезаписать адрес возврата.** Если ввести ещё больше - дойдёшь до адреса возврата и подменишь
   его на адрес нужной функции (например, спрятанной функции `win()`, которая печатает флаг). Когда
   функция "вернётся", она прыгнет туда, куда ты указал.

```
   [ buf ][ ... ][ адрес возврата ]
    AAAAAAAA....  адрес функции win()   <- программа "вернётся" в win()
```

💡 Признак pwn-задачи: бинарник + адрес `IP:ПОРТ`, во вводе нет проверки длины, а в коде/строках
есть подозрительная функция вроде `win`, `secret`, `system`, которую "никто не вызывает". Цель -
доехать вводом до адреса возврата и подставить её адрес. Сам ввод отправляют скриптом (глава 7:
`socket`/`pwntools`), потому что в нём есть "непечатные" байты адреса.

## 9.3. Переполнение целого (Integer Overflow)

Числа в программе имеют ограниченный размер. Если прибавить к максимуму - значение "перескакивает"
через край (как одометр с 9999 на 0000).

```c
uint8_t x = 255;
x = x + 1;        // не 256, а 0 (байт вмещает только 0..255)
```

Как эксплуатируют: проверка вроде `if (len <= 100) allow();` можно обойти, если `len` переполнится и
из большого числа станет маленьким (или отрицательным), проскочив проверку, хотя реальных данных
много. Или: цена `0`, умноженная хитро, "оборачивается" в выгодное значение.

💡 Это та же `& 0xFF`-арифметика, что в главе 4. Понимание "числа переполняются по кругу" - уже
половина таких задач.

---

## 9.4. Что реально делать на туре

- Опознать pwn (бинарник + порт, нет проверки длины, есть "лишняя" функция).
- Найти, **сколько** байт нужно до нужного места (размер буфера из кода/Ghidra - п. 8.4).
- Собрать ввод: `b"A" * N + нужные_байты` и отправить скриптом из главы 7.
- Полноценную эксплуатацию (ROP, обход защит) оставить на регион - это 🔺🔺.

> Pwn целиком - тема следующих этапов. Но идею ты ухватил: длинный ввод затирает соседнюю переменную
> или адрес возврата, а числа переполняются по кругу. Этого хватает, чтобы опознать pwn-задачу и взять
> самый простой вариант. ROP и обход защит начинаются уже не здесь.
