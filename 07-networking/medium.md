# Глава 7. Сети

В задачах с **сервисом** дают адрес `IP:ПОРТ`: подключись, ответь на вопросы сервера и получи флаг.
Разберём ручное подключение и **автоматизацию** диалога.

---

## 7.1. Как устроена сеть: модели, IP, порт, TCP

- **IP-адрес** - адрес машины в сети (`10.0.0.5`). **Порт** - номер "двери" на этой машине
  (`31337`). Вместе `IP:ПОРТ` однозначно указывают на конкретный сервис.
- **TCP** - надёжное соединение-"труба": что отправил, то и дойдёт по порядку. Большинство
  CTF-сервисов - TCP. (UDP - без гарантий, встречается реже.)
- Сервис по адресу обычно работает так: **читает** твой ввод, что-то считает, **пишет** ответ.
  Твоя задача - понять протокол общения и дать то, что он ждёт.

### Модель OSI и TCP/IP - зачем они тебе

**OSI** описывает сеть в 7 уровнях, **TCP/IP** - в 4. Уровни помогают определить,
где искать проблему и какой инструмент выбрать.

| OSI (7) | Уровень TCP/IP | Что живёт тут | Пример в CTF | Инструмент |
|---|---|---|---|---|
| 7 Приложений / 6 Представления / 5 Сеансовый | **Приложений** | HTTP, DNS, FTP, SSH, сам протокол сервиса | веб-задача, диалог с сервисом | `curl`, `nc`, `socket` |
| 4 Транспортный | **Транспортный** | TCP и UDP, **порты** | "подключись к `IP:ПОРТ`" | `nc`, `socket`, `nmap` |
| 3 Сетевой | **Межсетевой** | IP-адреса, маршруты, **маски** | "почему нет связи", подсети | `ip`, `ping`, маски (п. 7.5) |
| 2 Канальный / 1 Физический | **Доступа к среде** | MAC-адреса, Ethernet, Wi-Fi, кабель | ARP, разбор дампа трафика | Wireshark, `scapy` |

Диалог по `IP:ПОРТ` - транспортный и прикладной уровни (`nc`/`socket`, п. 7.2-7.4);
адреса и маски - сетевой (п. 7.5). Дамп `.pcap` может содержать несколько уровней
(разбор - `05-forensics-stego`).

💡 Ищи ошибку **снизу вверх**: сначала доступность адреса и порта (`ping`, `nc -vz`),
затем правильность диалога с сервисом.

## 7.2. `nc` (netcat) - подключиться и поговорить руками

`nc` (netcat) открывает соединение с сервисом:

```bash
nc 10.0.0.5 31337          # подключиться к IP на порт 31337
```

После подключения просто печатаешь ответы и жмёшь Enter. Сервер пишет - ты читаешь прямо в
терминале. Этого достаточно для простых диалоговых задач.

Полезные варианты:

```bash
nc -v 10.0.0.5 31337       # -v = подробно (видно, установилось ли соединение)
echo "42" | nc 10.0.0.5 31337          # сразу отправить строку и получить ответ
nc 10.0.0.5 31337 < input.txt          # скормить заготовленный ввод из файла
nc -lvp 9999                            # слушать порт (в netcat-openbsd: nc -lv 9999, без -p)
```

💡 Сначала прочитай приглашение сервера через `nc`: в нём часто описан протокол.

🎯 **Тренировка 19.** Сделай "сервер, отдающий флаг": в одном окне
`echo "flag{netcat_master}" | nc -lv 9999`. В другом - **забери флаг и сразу обработай**:
`nc 127.0.0.1 9999 | grep flag`. Так ты и подключаешься, и фильтруешь ответ сервера одной цепочкой.

## 7.3. Когда руками неудобно - Python `socket`

Для многих раундов или короткого тайм-аута напиши скрипт на встроенном модуле `socket`:

```python
import socket

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)   # создать TCP-сокет
s.connect(("10.0.0.5", 31337))                           # подключиться (IP, порт)

print(s.recv(1024))          # прочитать до 1024 байт (вопрос сервера)
s.sendall(b"42\n")           # отправить ответ - ОБЯЗАТЕЛЬНО байты и с \n на конце!
print(s.recv(1024))          # прочитать ответ (часто здесь флаг)

s.close()
```

⚠️ Три главные ошибки новичков:
1. **Отправлять строку вместо байтов** - `sendall` принимает `bytes`, пиши `b"..."` или `.encode()`.
2. **Забыть `\n`** в конце - сервер обычно читает "строку до перевода", без `\n` он будет ждать
   вечно.
3. **Читать не вовремя** - если сервер ещё не прислал данные, `recv` подождёт; если прислал больше
   1024 байт - дочитай ещё раз.

### Шаблон "вопрос-ответ в цикле"

Частый случай: сервер задаёт серию задачек (например, "посчитай выражение") и в конце отдаёт флаг.
Автоматизируем:

```python
import socket

s = socket.socket()
s.connect(("10.0.0.5", 31337))

f = s.makefile("rwb")        # удобно читать построчно, как файл

for _ in range(100):         # сервер может гонять много раундов
    line = f.readline()      # прочитать строку-вопрос
    print(line)
    if b"flag" in line:      # проверяем флаг ДО eval - иначе eval упадёт на строке с флагом!
        break
    # пример: сервер прислал "12 + 30"
    expr = line.decode().strip()
    answer = str(eval(expr))          # посчитать (eval только для ДОВЕРЕННОГО формата!)
    f.write(answer.encode() + b"\n")  # отправить ответ
    f.flush()                         # ВАЖНО: протолкнуть буфер
```

💡 `s.makefile("rwb")` + `readline()` избавляет от возни с `recv` по кусочкам, когда сервер общается
строками. Не забывай `flush()` после записи - иначе ответ "застрянет" в буфере.

Затем напиши клиента: прочитать -> посчитать -> отправить -> получить флаг.

## 7.4. `pwntools` - если установлен

🔺 `pwntools` - библиотека, которая делает сетевое общение (и pwn-задачи) короче. Удобнее так:

```python
from pwn import *

io = remote("10.0.0.5", 31337)   # подключиться
print(io.recvline())              # прочитать строку
io.sendline(b"42")                # отправить (sendline сам добавит \n)
print(io.recvline())              # прочитать ответ
io.interactive()                  # перейти в ручной режим (дочитать/дописать самому)
```

Полезные методы: `recvline()` (строка), `recvuntil(b":")` (читать до подстроки), `sendline(b"...")`
(отправить со `\n`), `interactive()` (ручной режим). Если `pwntools` нет - всё то же делается на
чистом `socket` из п. 7.3, просто чуть длиннее.

## 7.5. Подсети и маски: как считать

По адресу и маске можно найти сеть, число хостов и проверить, в одной ли подсети две машины.
Разберём расчёт вручную и через Python.

### Что такое маска и запись `/N`

Маска делит IP на две части: **сеть** (общая для всех в подсети) и **хост** (номер машины внутри).
Запись `/24` (CIDR) значит "первые 24 бита из 32 - это сеть". Маска и `/N` - одно и то же:

| /N | Маска | Адресов в блоке | Полезных хостов |
|---|---|---|---|
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| /26 | 255.255.255.192 | 64 | 62 |
| /27 | 255.255.255.224 | 32 | 30 |
| /28 | 255.255.255.240 | 16 | 14 |
| /30 | 255.255.255.252 | 4 | 2 |

Правило: **адресов в блоке = 2^(32 - N)**, полезных хостов на два меньше (минус адрес сети и минус
широковещательный). Для `/24` это `2^8 = 256`, для `/26` - `2^6 = 64`.

### Глазами: совпадают ли подсети

Для "круглых" масок достаточно сравнить начало адреса:
- **/24** - совпадают **первые три** числа (`192.168.1.5` и `192.168.1.200` - вместе, а `192.168.2.5`
  уже в другой подсети);
- **/16** - совпадают **первые два** числа;
- **/8** - совпадает **первое** число.

### Нестандартная маска (/26, /27): метод "размер блока"

Когда маска не круглая, работает быстрый приём в одном (последнем) октете. Возьмём `192.168.1.70/26`:

1. **Размер блока = 256 - число_в_маске.** Маска `/26` -> `255.255.255.192` -> блок `256 - 192 = 64`.
2. **Границы подсетей** идут шагом в блок: `.0`, `.64`, `.128`, `.192`.
3. **Адрес сети** - ближайшая граница снизу. `70` попадает в блок `.64` (между 64 и 127).
4. **Широковещательный** - конец блока: `.64 + 64 - 1 = .127`.
5. **Хосты** - между ними: `.65 ... .126` (это `64 - 2 = 62` штуки).

Значит `192.168.1.70` и `192.168.1.100` - в **одной** подсети (оба в блоке `.64`), а
`192.168.1.70` и `192.168.1.200` - в **разных** (`.64` против `.192`).

Тот же расчёт в коде - на случай, если считаешь на выданной машине:

```python
ip_last, mask_last = 70, 192        # последний октет адреса и маски (для /26)
block = 256 - mask_last             # размер блока = 64
net = (ip_last // block) * block    # адрес сети в этом октете = 64
print("сеть  .", net)               # -> 64
print("бродк .", net + block - 1)   # -> 127
print("хостов", block - 2)          # -> 62
```

### Побитовый взгляд (откуда это всё)

Адрес сети - это IP, у которого хостовые биты обнулены. Формально это **логическое И (AND)** адреса и
маски по битам:

```python
ip   = [192, 168, 1, 70]
mask = [255, 255, 255, 192]
net  = [o & m for o, m in zip(ip, mask)]    # & = побитовое И
print(net)                                   # -> [192, 168, 1, 64]
```

`70` в двоичном - `01000110`, `192` - `11000000`; их `AND` = `01000000` = `64`. Вот почему сеть - `.64`.

### Самый надёжный способ: модуль `ipaddress`

Встроенный `ipaddress` проверит расчёты без интернета и установки пакетов:

```python
import ipaddress as ip

net = ip.ip_network("192.168.1.64/26")
print(net.netmask)              # 255.255.255.192
print(net.num_addresses)        # 64  (всего адресов в блоке)
print(net.network_address)      # 192.168.1.64   (адрес сети)
print(net.broadcast_address)    # 192.168.1.127  (широковещательный)
print(list(net.hosts())[0], list(net.hosts())[-1])   # 192.168.1.65 192.168.1.126

# в одной ли подсети два адреса? сравниваем адрес сети при strict=False:
a = ip.ip_network("192.168.1.70/26",  strict=False).network_address
b = ip.ip_network("192.168.1.100/26", strict=False).network_address
print(a == b)                   # True  (оба -> 192.168.1.64)

# быстрый "лежит ли адрес в подсети":
print(ip.ip_address("192.168.1.70") in ip.ip_network("192.168.1.64/26"))   # True
```

## 7.6. Диагностика сети: ip, ping, DNS, iptables

Иногда сеть - это не сервис, а **задача на понимание**: дают схему или вывод команд и просят
объяснить, почему связь не работает. Полезный минимум команд:

```bash
ip addr          # какие IP у интерфейсов (мой адрес и маска подсети)
ip route         # таблица маршрутов; есть ли "default via ..." (шлюз в интернет)
ping 10.0.0.1    # доходит ли пакет до адреса
nslookup host    # резолвится ли имя в IP (работает ли DNS)
```

Типичные причины "нет связи", которые читаются по выводу:
- нет строки `default via ...` в `ip route` -> **не задан шлюз** (локально пингуется, наружу нет);
- `ping` шлюза не проходит -> **не та подсеть/маска** или шлюз недоступен (проверь маску, п. 7.5);
- пинг по IP работает, а по имени нет -> **проблема с DNS** (`nslookup` молчит/ошибка);
- адрес в чужой подсети -> машина физически не в той сети;
- всё верно, а порт "закрыт" -> возможно, режет **файрвол** (см. ниже).

### iptables - файрвол Linux

`iptables` решает для каждого пакета: пропустить (`ACCEPT`), выкинуть молча (`DROP`) или отклонить с
ответом (`REJECT`). Правила собраны в **цепочки**: `INPUT` (входящие нам), `OUTPUT` (исходящие от
нас), `FORWARD` (транзит). В CTF это встречается как "вот правила - объясни, пройдёт ли пакет" или
"почему сервис недоступен снаружи".

Посмотреть правила:

```bash
iptables -L -n -v --line-numbers   # -n = не резолвить имена (быстрее и честнее), -v = подробно
```

Как читать: пакет идёт по цепочке **сверху вниз**, срабатывает **первое подходящее** правило. Если ни
одно не подошло - применяется **политика цепочки** (`policy` в заголовке). Пример набора:

```bash
iptables -P INPUT DROP                               # политика по умолчанию: всё входящее DROP
iptables -A INPUT -i lo -j ACCEPT                    # разрешить localhost
iptables -A INPUT -m state --state ESTABLISHED -j ACCEPT   # ответы на наши соединения
iptables -A INPUT -p tcp --dport 22 -j ACCEPT        # разрешить SSH (порт 22)
```

Здесь разрешены localhost, установленные соединения и новые TCP-соединения на порт 22.
Запрос на порт 80 попадёт под политику `DROP`: для веба нужно правило `-p tcp --dport 80 -j ACCEPT`.

Что значат флаги правила: `-A INPUT` добавить в цепочку INPUT, `-p tcp` протокол, `--dport 22`
порт назначения, `-s 10.0.0.0/24` источник (вот где нужны маски!), `-j ACCEPT/DROP/REJECT` что
сделать. `-A` добавляет в конец, `-I` вставляет в начало, `-D` удаляет, `-P` задаёт политику.

⚠️ `ACCEPT` **после** общего `DROP` для того же трафика не сработает: пакет до него не дойдёт.
На муниципале обычно нужно прочитать готовые правила, а не настраивать файрвол.

## 7.7. SSH: удалённый доступ и перенос файлов

SSH (Secure Shell) даёт защищённый доступ к удалённой машине. Если в задаче дали логин с паролем
или ключ, подключись и ищи флаг на сервере:

```bash
ssh user@10.0.0.5                 # подключиться (спросит пароль)
ssh user@10.0.0.5 -p 2222         # нестандартный порт (-p, маленькая буква!)
ssh user@10.0.0.5 'cat /flag.txt' # выполнить одну команду и выйти, не заходя в оболочку
```

⚠️ При первом подключении сверь отпечаток сервера с данными организаторов, затем подтверди `yes`.
Порт у `ssh` задаётся маленькой `-p`, у `scp` - большой `-P`.

Перенос файлов - `scp` (копирование поверх SSH):

```bash
scp user@10.0.0.5:/flag.txt .            # скачать файл с сервера в текущую папку
scp data.bin user@10.0.0.5:/tmp/         # загрузить файл на сервер
scp -P 2222 user@10.0.0.5:/flag.txt .    # порт - большая -P
```

Если дали **ключ** вместо пароля (файл `id_rsa` или `key.pem`):

```bash
chmod 600 key.pem                 # ssh не примет ключ, доступный всем (иначе ошибка прав)
ssh -i key.pem user@10.0.0.5      # -i = войти по этому ключу
```

🔺 Проброс порта: если на сервере сервис слушает только локально (например, БД на 3306), его можно
"вытащить" к себе на машину:

```bash
ssh -L 8080:127.0.0.1:3306 user@10.0.0.5   # локальный 8080 -> порт 3306 внутри сервера
```

🔺 Подбор пароля к SSH - `hydra` (когда дан список логинов/паролей; только по своим стендам):

```bash
hydra -l user -P words.txt ssh://10.0.0.5        # перебор пароля для логина user
hydra -L users.txt -P words.txt ssh://10.0.0.5   # перебор и логина, и пароля
```

💡 На туре SSH чаще не "ломают", а используют по готовым данным: дали доступ - зашёл, осмотрелся
(`ls`, `cat`, `sudo -l`), забрал флаг. Попробуй сам: включи вход по SSH на своей же машине и
потренируйся заходить (`ssh localhost`) и копировать файлы через `scp`.

## 7.8. Wireshark и tcpdump: смотрим, что летит по сети

Wireshark показывает пакеты клиента и сервера. Здесь разберём захват и быстрый просмотр трафика.
Подробный разбор `.pcap` (фильтры, Follow Stream, извлечение файлов, DNS/USB) -
в `05-forensics-stego`, п. 5.7 и hard.

**Снять трафик** (свой, на своей машине - для тренировки или чтобы увидеть, что шлёт твой скрипт):

```bash
sudo tcpdump -i lo -w my.pcap              # писать трафик loopback в файл (Ctrl+C - стоп)
sudo tcpdump -i any port 5000 -w my.pcap   # только порт 5000 на любом интерфейсе
```

В Wireshark то же самое мышкой: выбрать интерфейс -> начать захват -> остановить -> сохранить.

⚠️ Два разных вида фильтров, их часто путают:
- **Capture filter** (при захвате, синтаксис BPF): `tcp port 80`, `host 10.0.0.5` - что вообще писать.
- **Display filter** (при просмотре, синтаксис Wireshark): `http`, `tcp.port == 80`,
  `ip.addr == 10.0.0.5`, `frame contains "flag"` - что показать из уже записанного.

**Быстро глянуть содержимое** - без GUI и офлайн:

```bash
strings my.pcap | grep -iE 'flag|pass|user|GET|POST'   # самый быстрый просмотр
tshark -r my.pcap -Y http                               # HTTP-пакеты (tshark = Wireshark в терминале)
tshark -r my.pcap -qz follow,tcp,ascii,0                # собрать первый TCP-поток целиком
```

💡 Для отладки скрипта (п. 7.3) захвати трафик нужного порта и сравни отправленные и полученные
байты. Сборка данных из пакетов, Base64/hex и эксфильтрация через DNS разобраны в форензике, п. 5.7.

## 7.9. Сети: "вижу X -> делаю Y"

| Что видишь | Что делать |
|---|---|
| дан `IP ПОРТ`, "подключитесь" | `nc IP ПОРТ`, прочитать, что говорит сервер |
| сервер задаёт один вопрос | ответить руками в `nc` |
| сервер гоняет много раундов / мало времени | скрипт на `socket` (цикл читать-считать-писать) |
| есть `pwntools` | `remote()`, `recvline`/`sendline`, `interactive()` |
| вопрос "в одной ли подсети", адрес сети, число хостов | маски: метод "размер блока" или `ipaddress` (п. 7.5) |
| дали схему сети / вывод `ip route` | искать: шлюз, маску, DNS (п. 7.6) |
| дали логин/пароль или ключ к серверу | зайти `ssh user@host`, забрать флаг; файлы - `scp` (п. 7.7) |
| дали дамп `.pcap` / надо увидеть трафик | Wireshark/`tshark`; снять - `tcpdump -w`; разбор - форензика п. 5.7 |
| дали набор правил `iptables` | читать сверху вниз, первое совпадение, иначе политика (п. 7.6) |
| не ясно, на каком уровне проблема | определить уровень по модели (п. 7.1), чинить снизу вверх |

> В сетевом скрипте проверяй байты, `\n` и `flush`. Дальше - реверс.
